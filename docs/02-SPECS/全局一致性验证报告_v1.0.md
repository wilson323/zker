### 5.2 错误响应格式对比

#### 格式1: RAG文档

```json
{
  "code": "KNOWLEDGE_NOT_FOUND",
  "message": "知识库不存在",
  "message_en": "Knowledge not found",
  "details": {
    "knowledge_id": 123
  },
  "request_id": "req_1234567890",
  "timestamp": "2025-01-03T12:00:00Z"
}
```

#### 格式2: 代码质量文档

```json
{
  "code": "BOT_NOT_FOUND",
  "message": "Bot不存在",
  "message_zh": "Bot不存在",
  "message_en": "Bot not found",
  "data": {
    "bot_id": "bot_123"
  },
  "request_id": "req_1234567890",
  "timestamp": "2025-01-03T12:00:00Z"
}
```

**不一致点**:
1. `details` vs `data` ⚠️
2. `message_en` vs `message_zh` + `message_en` ⚠️

**建议**: 统一使用以下格式

```json
{
  "code": "ERROR_CODE",
  "message": "错误描述",
  "message_zh": "中文错误描述",
  "message_en": "English error message",
  "details": {
    "key": "value"
  },
  "request_id": "req_xxx",
  "timestamp": "2025-01-03T12:00:00Z"
}
```

**优先级**: P1 (中)

## 8. 术语字典

### 8.1 核心术语定义

| 术语 | 英文 | 定义 | 示例 |
|-----|------|------|------|
| 租户 | Tenant | 系统中的独立组织或企业，拥有完全隔离的数据和配置 | 企业A、企业B |
| 隔离 | Isolation | 确保不同租户的数据和资源互不可见的技术手段 | 数据库隔离、缓存隔离 |
| 知识库 | Knowledge Base (KB) | 存储和管理文档、数据的容器，支持向量检索和全文检索 | 企业文档库 |
| 向量检索 | Vector Search | 基于向量相似度的语义检索技术 | 基于embedding的语义搜索 |
| 全文检索 | Full-Text Search (FTS) | 基于关键词的文本检索技术 | Elasticsearch搜索 |
| 智能体 | Agent | 具备自主决策和执行能力的AI实体 | ChatBot、工作流Bot |
| 工作流 | Workflow | 由多个节点组成的业务流程编排 | 审批流程、RAG流程 |
| 插件 | Plugin | 可扩展的功能模块，支持热插拔 | HTTP工具、数据库工具 |
| 请求上下文 | Request Context | 包含租户ID、用户ID等元数据的请求上下文 | tenant_id、user_id |
| 领域服务 | Domain Service | 核心业务逻辑的实现 | TenantService、BotService |
| 仓储 | Repository | 数据访问的抽象接口 | BotRepository、KnowledgeRepository |
| 实体 | Entity | 领域模型的核心对象 | Tenant、Bot、Knowledge |
| 数据传输对象 | Data Transfer Object (DTO) | 跨层传输的数据结构 | CreateBotRequest、BotInfo |
| 应用服务 | Application Service | 用例编排和事务管理 | BotApplicationService |
