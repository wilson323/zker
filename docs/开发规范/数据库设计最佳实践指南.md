## 1. 设计原则

### 1.1 核心原则

| 原则 | 说明 | 优先级 |
|------|------|--------|
| **规范化与反规范化平衡** | 第三范式，但允许适度冗余 | P0 |
| **数据一致性** | 使用外键保证引用完整性 | P0 |
| **最小权限原则** | 数据库用户权限最小化 | P0 |
| **可扩展性** | 预留扩展字段，使用JSON字段 | P1 |
| **性能优先** | 合理使用索引、分区、缓存 | P0 |
| **安全优先** | 敏感数据加密、审计日志 | P0 |

### 1.2 命名规范

#### 1.2.1 表命名

```sql
-- ✅ 正确示例
users                    -- 用户表（复数）
user_roles              -- 用户角色关联表（双表名，下划线连接）
bot_prompts              -- Bot提示词表
conversation_messages    -- 对话消息表

-- ❌ 错误示例
user                    -- 单数形式（不推荐）
userInfo                -- 驼峰命名（不推荐）
user_info               -- 使用info后缀（不推荐）
tb_user                 -- 使用tb前缀（不推荐）
```

**命名规则**：
- ✅ 全部小写
- ✅ 使用下划线分隔
- ✅ 使用复数形式
- ✅ 见名知意
- ❌ 不使用数字开头
- ❌ 不使用MySQL保留字
- ❌ 不超过64个字符

#### 1.2.2 字段命名

```sql
-- ✅ 正确示例
id                      -- 主键
tenant_id               -- 租户ID（外键）
user_name               -- 用户名
email                   -- 邮箱
created_at              -- 创建时间
updated_at              -- 更新时间
is_active               -- 布尔值（is_前缀）
has_permission          -- 布尔值（has_前缀）

-- ❌ 错误示例
userName               -- 驼峰命名
Email                   -- 首字母大写
user_name               -- 冗余前缀（users表的字段）
name1, name2            -- 数字后缀（含义不清）
```

**命名规则**：
- ✅ 全部小写
- ✅ 使用下划线分隔
- ✅ 外键字段：`{关联表}_id`
- ✅ 布尔值：`is_` / `has_` / `can_` 前缀
- ✅ 时间戳：`_at` 后缀
- ❌ 不使用缩写（除通用缩写如id、url、ip）
- ❌ 不使用数据库保留字

## 2. 表设计规范

### 2.1 表结构模板

```sql
CREATE TABLE {table_name} (
    -- 主键
    id {datatype} PRIMARY KEY COMMENT '主键ID',

    -- 租户字段（所有业务表必须有）
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 业务字段
    {field1} {datatype} {constraints} COMMENT '字段1说明',
    {field2} {datatype} {constraints} COMMENT '字段2说明',

    -- 元数据字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    created_by BIGINT COMMENT '创建人ID',
    updated_by BIGINT COMMENT '更新人ID',
    deleted_at DATETIME COMMENT '删除时间（软删除）',

    -- 索引
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_created_at (created_at),
    INDEX idx_deleted_at (deleted_at),

    -- 外键
    FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,
    FOREIGN KEY (created_by) REFERENCES users(id),
    FOREIGN KEY (updated_by) REFERENCES users(id)

) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci
  COMMENT='表的说明';
```

### 2.2 字段顺序规范

**按以下顺序排列字段**：

1. **主键** (`id`)
2. **租户ID** (`tenant_id`) - 多租户表必须有
3. **外键字段** (如 `user_id`, `bot_id`)
4. **业务字段** - 按重要性排序
5. **状态字段** (`status`, `type`)
6. **配置字段** (`settings` JSON)
7. **元数据字段** (`created_at`, `updated_at`, `deleted_at`)

**示例**：
```sql
CREATE TABLE bots (
    -- 1. 主键
    id VARCHAR(64) PRIMARY KEY COMMENT 'Bot ID',

    -- 2. 租户ID
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 3. 外键字段
    creator_id BIGINT NOT NULL COMMENT '创建者ID',
    owner_id BIGINT COMMENT '所有者ID',

    -- 4. 业务字段
    name VARCHAR(100) NOT NULL COMMENT 'Bot名称',
    description VARCHAR(500) COMMENT 'Bot描述',
    avatar VARCHAR(512) COMMENT 'Bot头像URL',

    -- 5. 状态字段
    status ENUM('draft', 'published', 'archived') NOT NULL DEFAULT 'draft' COMMENT '状态',
    type ENUM('chat', 'workflow', 'agent') NOT NULL DEFAULT 'chat' COMMENT '类型',

    -- 6. 配置字段
    settings JSON COMMENT 'Bot配置',

    -- 7. 元数据字段
    published_at DATETIME COMMENT '发布时间',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    created_by BIGINT COMMENT '创建人ID',
    updated_by BIGINT COMMENT '更新人ID',
    deleted_at DATETIME COMMENT '删除时间（软删除）'
);
```

### 2.3 必须字段

**所有业务表必须包含以下字段**：

```sql
-- 1. 租户ID（多租户隔离）
tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

-- 2. 审计字段
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
created_by BIGINT COMMENT '创建人ID',
updated_by BIGINT COMMENT '更新人ID',

-- 3. 软删除字段（重要数据表必须有）
deleted_at DATETIME COMMENT '删除时间（软删除）',
```

**可选字段**：

```sql
-- 版本控制字段（需要版本控制的表）
version INT NOT NULL DEFAULT 1 COMMENT '版本号',

-- 扩展字段（预留扩展空间）
ext_data JSON COMMENT '扩展数据',

-- 租户级配置（租户自定义配置）
tenant_settings JSON COMMENT '租户自定义配置',
```

## 3. 字段设计规范

### 3.1 数据类型选择

#### 3.1.1 整数类型

| 类型 | 字节数 | 范围 | 适用场景 |
|------|-------|------|---------|
| `TINYINT` | 1 | -128 ~ 127 | 状态值、枚举值、小范围计数 |
| `SMALLINT` | 2 | -32,768 ~ 32,767 | 中等范围计数 |
| `INT` | 4 | -2.1亿 ~ 2.1亿 | 计数器、外键ID |
| `BIGINT` | 8 | -9.2×10¹⁸ ~ 9.2×10¹⁸ | 主键ID、大范围计数 |

**示例**：
```sql
-- ✅ 正确示例
status TINYINT NOT NULL DEFAULT 0 COMMENT '状态: 0-禁用, 1-启用',
message_count INT NOT NULL DEFAULT 0 COMMENT '消息数量',
id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',

-- ❌ 错误示例
status INT NOT NULL DEFAULT 0  -- 浪费空间（应该用TINYINT）
id INT PRIMARY KEY AUTO_INCREMENT  -- 可能不够用（应该用BIGINT）
```

#### 3.1.2 字符串类型

| 类型 | 最大长度 | 存储需求 | 适用场景 |
|------|---------|---------|---------|
| `CHAR(n)` | 255 | n字节 | 固定长度字符串（如MD5、UUID） |
| `VARCHAR(n)` | 65,535 | 实际长度+1/2 | 变长字符串 |
| `TEXT` | 65,535 | 实际长度+2 | 长文本 |

**示例**：
```sql
-- ✅ 正确示例
subdomain VARCHAR(63) NOT NULL COMMENT '子域名（RFC 1034最大63字符）',
mfa_secret CHAR(32) NOT NULL COMMENT 'MFA密钥（固定32字符）',
content TEXT COMMENT '长文本内容',

-- ❌ 错误示例
name VARCHAR(255)  -- 如果名称不会很长，应该用VARCHAR(100)
mfa_secret VARCHAR(32)  -- 固定长度应该用CHAR
```

**VARCHAR长度建议**：
- 用户名/邮箱/手机号：`VARCHAR(255)`（有唯一索引）
- 名称/标题：`VARCHAR(100)` 或 `VARCHAR(200)`
- 描述/备注：`VARCHAR(500)`
- URL/路径：`VARCHAR(512)` 或 `VARCHAR(1024)`

#### 3.1.3 时间类型

| 类型 | 范围 | 适用场景 |
|------|------|---------|
| `DATE` | 1000-01-01 ~ 9999-12-31 | 日期（生日、入职日期） |
| `TIME` | -838:59:59 ~ 838:59:59 | 时间（不推荐，用DATETIME代替） |
| `DATETIME` | 1000-01-01 00:00:00 ~ 9999-12-31 23:59:59 | 日期时间 |
| `TIMESTAMP` | 1970-01-01 00:00:01 ~ 2038-01-19 03:14:07 | 时间戳（受时区影响） |

**推荐使用**：`DATETIME` 或 `TIMESTAMP`

```sql
-- ✅ 正确示例
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
deleted_at DATETIME COMMENT '删除时间（软删除）',
birth_date DATE COMMENT '生日',

-- ❌ 错误示例
create_time VARCHAR(20)  -- 不要用字符串存储时间
```

#### 3.1.4 布尔类型

MySQL没有原生的BOOLEAN类型，使用`TINYINT(1)`代替：

```sql
-- ✅ 正确示例
is_active TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否激活: 0-否, 1-是',
mfa_enabled TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否启用MFA',
is_deleted TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否删除',

-- ✅ 也允许使用BOOLEAN（MySQL会自动转换为TINYINT(1)）
is_published BOOLEAN NOT NULL DEFAULT FALSE COMMENT '是否发布',
```

#### 3.1.5 枚举类型

```sql
-- ✅ 方式1：使用ENUM（性能好，但不利于扩展）
status ENUM('active', 'inactive', 'suspended') NOT NULL DEFAULT 'active' COMMENT '状态',

-- ✅ 方式2：使用TINYINT + 注释（更灵活）
status TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 1-激活, 2-禁用, 3-停用',

-- ✅ 方式3：使用VARCHAR + CHECK约束（最灵活）
status VARCHAR(20) NOT NULL DEFAULT 'active' COMMENT '状态',
CONSTRAINT chk_status CHECK (status IN ('active', 'inactive', 'suspended'))
```

**推荐**：
- 状态值**固定**且**不会变更**：使用`ENUM`
- 状态值**可能变更**或**需要国际化**：使用`TINYINT` + 数据字典
- 跨模块的状态：使用`TINYINT`（统一数据字典）

#### 3.1.6 JSON类型

MySQL 5.7+ 支持JSON类型，用于存储半结构化数据：

```sql
-- ✅ 正确示例1：配置信息
settings JSON COMMENT '用户设置 {"theme":"dark","language":"zh-CN"}',

-- ✅ 正确示例2：扩展字段
ext_data JSON COMMENT '扩展数据（预留扩展空间）',

-- ✅ 正确示例3：标签/属性数组
tags JSON COMMENT '标签数组 ["tag1","tag2","tag3"]',

-- ✅ 正确示例4：复杂对象
metadata JSON COMMENT '元数据 {"source":"web","campaign":"q1_2025"}',
```

**JSON字段最佳实践**：
1. ✅ 添加注释说明JSON结构
2. ✅ 不频繁查询JSON字段内部内容
3. ✅ 使用JSON函数查询时添加生成列（Generated Column）
4. ✅ 重要字段不要放入JSON（无法建索引）

**JSON函数示例**：
```sql
-- 提取JSON字段
SELECT
    id,
    JSON_EXTRACT(settings, '$.theme') AS theme,
    JSON_EXTRACT(settings, '$.language') AS language
FROM users;

-- JSON字段索引（通过生成列）
ALTER TABLE users
ADD COLUMN theme VARCHAR(20) AS (JSON_UNQUOTE(JSON_EXTRACT(settings, '$.theme'))) STORED;

CREATE INDEX idx_theme ON users(theme);
```

#### 3.1.7 金额/货币

**不要使用FLOAT或DOUBLE存储金额**（精度丢失问题），使用`DECIMAL`：

```sql
-- ✅ 正确示例
amount DECIMAL(18, 2) NOT NULL DEFAULT 0.00 COMMENT '金额（元）',
price DECIMAL(10, 2) NOT NULL COMMENT '单价（分）',

-- DECIMAL(18, 2)说明：
-- 18: 总位数（整数部分 + 小数部分）
-- 2: 小数位数
-- 范围: -99999999999999999.99 ~ 99999999999999999.99
```

**金额存储建议**：
- 小额支付：用**分**为单位存储`BIGINT`（避免精度问题）
- 大额财务：用`DECIMAL(18, 2)`
- 汇率：用`DECIMAL(18, 6)`

```sql
-- ✅ 推荐：以分为单位
price BIGINT NOT NULL DEFAULT 0 COMMENT '单价（分）',

-- 转换示例
SELECT price / 100.0 AS price_yuan FROM products;
```

### 3.2 字段约束

#### 3.2.1 NOT NULL约束

**原则**：核心业务字段必须有`NOT NULL`约束

```sql
-- ✅ 正确示例
tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
user_id BIGINT NOT NULL COMMENT '用户ID',
status TINYINT NOT NULL DEFAULT 1 COMMENT '状态',
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',

-- ❌ 错误示例
tenant_id VARCHAR(64) COMMENT '租户ID',  -- 应该NOT NULL
status INT COMMENT '状态',               -- 应该NOT NULL并设置DEFAULT
```

#### 3.2.2 DEFAULT值

**原则**：所有字段都应该有合理的DEFAULT值

```sql
-- ✅ 正确示例
status TINYINT NOT NULL DEFAULT 1 COMMENT '状态',
is_active TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否激活',
message_count INT NOT NULL DEFAULT 0 COMMENT '消息数量',
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',

-- ❌ 错误示例
status TINYINT NOT NULL COMMENT '状态',  -- 没有DEFAULT，插入时必须显式指定
```

**DEFAULT值选择**：
- 数值类型：`0`
- 字符串类型：`''`（空字符串）或`'N/A'`
- 布尔类型：`0`（FALSE）或`1`（TRUE）
- 枚举类型：默认值
- 时间类型：`CURRENT_TIMESTAMP`（除deleted_at）

#### 3.2.3 COMMENT注释

**原则**：所有字段必须有COMMENT注释

```sql
-- ✅ 正确示例
id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
email VARCHAR(255) NOT NULL COMMENT '邮箱',
status TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 1-激活, 2-禁用, 3-锁定',

-- ❌ 错误示例
id BIGINT PRIMARY KEY AUTO_INCREMENT,      -- 缺少注释
email VARCHAR(255) NOT NULL,               -- 缺少注释
```

**COMMENT格式**：
- 简单字段：`'邮箱'`
- 带单位字段：`'文件大小（字节）'`
- 枚举字段：`'状态: 1-激活, 2-禁用, 3-锁定'`
- 外键字段：`'租户ID'`（关联表名）或`'创建人ID'`

## 4. 索引设计规范

### 4.1 索引类型

| 索引类型 | 语法 | 适用场景 |
|---------|------|---------|
| **主键索引** | `PRIMARY KEY` | 主键，自动创建 |
| **唯一索引** | `UNIQUE KEY` | 保证值唯一，如邮箱、用户名 |
| **普通索引** | `INDEX` | 加速查询 |
| **全文索引** | `FULLTEXT INDEX` | 全文搜索 |
| **复合索引** | `INDEX (col1, col2, ...)` | 多字段联合查询 |
| **空间索引** | `SPATIAL INDEX` | 地理位置查询 |

### 4.2 索引命名规范

```sql
-- ✅ 正确示例
PRIMARY KEY (id),                                    -- 主键
UNIQUE KEY uk_tenant_email (tenant_id, email),     -- 唯一索引
INDEX idx_tenant_id (tenant_id),                   -- 普通索引
FULLTEXT INDEX ft_content (content),                -- 全文索引
INDEX idx_tenant_status (tenant_id, status),       -- 复合索引

-- ❌ 错误示例
PRIMARY KEY (id),
UNIQUE KEY email (email),                          -- 缺少前缀
INDEX tenant_id (tenant_id),                        -- 缺少前缀
```

**命名规则**：
- 主键：`PRIMARY KEY (id)`
- 唯一索引：`uk_{字段名}`（unique key）
- 普通索引：`idx_{字段名}`（index）
- 全文索引：`ft_{字段名}`（fulltext）

### 4.3 索引设计原则

#### 4.3.1 选择性原则

**索引应该选择性高的字段**（即字段值重复率低）

```sql
-- ✅ 高选择性：适合建索引
INDEX idx_email (email),              -- 几乎唯一
INDEX idx_username (username),        -- 几乎唯一
INDEX idx_user_id (user_id),          -- 唯一

-- ❌ 低选择性：不适合建索引
INDEX idx_gender (gender),            -- 只有2-3个值
INDEX idx_is_active (is_active),      -- 只有2个值
INDEX idx_status (status),            -- 只有3-5个值
```

#### 4.3.2 最左前缀原则

**复合索引遵循最左前缀原则**：

```sql
-- 创建复合索引
INDEX idx_tenant_status_created (tenant_id, status, created_at);

-- ✅ 可以使用索引的查询
SELECT * FROM bots WHERE tenant_id = 'xxx';
SELECT * FROM bots WHERE tenant_id = 'xxx' AND status = 1;
SELECT * FROM bots WHERE tenant_id = 'xxx' AND status = 1 AND created_at > '2025-01-01';

-- ❌ 不能使用索引的查询
SELECT * FROM bots WHERE status = 1;                          -- 跳过了tenant_id
SELECT * FROM bots WHERE created_at > '2025-01-01';              -- 跳过了tenant_id和status
SELECT * FROM bots WHERE status = 1 AND created_at > '2025-01-01'; -- 跳过了tenant_id
```

**复合索引字段顺序**：
1. **选择性高的字段在前**：`tenant_id, status`（tenant_id选择性更高）
2. **查询频率高的字段在前**：经常单独查询的字段放在前面
3. **等值查询在前，范围查询在后**：`tenant_id, created_at`

#### 4.3.3 索引数量

**不要创建过多索引**：

- ❌ 每个表索引数不超过 **5个**（含主键）
- ❌ 复合索引字段数不超过 **3个**
- ✅ 索引不是越多越好，索引会降低写入性能

**建议**：
- 核心表（如users、bots）：5-8个索引
- 关联表（如user_roles）：2-3个索引
- 日志表：1-2个索引（主要按时间查询）

### 4.4 必须索引的字段

**所有表必须创建的索引**：

```sql
-- 1. 租户ID索引（多租户表必须有）
INDEX idx_tenant_id (tenant_id),

-- 2. 外键索引（提升JOIN性能）
INDEX idx_{外键字段} ({外键字段}),

-- 3. 创建时间索引（按时间范围查询）
INDEX idx_created_at (created_at),

-- 4. 删除时间索引（软删除表必须有）
INDEX idx_deleted_at (deleted_at),

-- 5. 状态索引（按状态筛选）
INDEX idx_status (status),
```

### 4.5 索引优化案例

#### 案例1：覆盖索引（Covering Index）

```sql
-- 查询语句
SELECT id, name, status FROM bots WHERE tenant_id = 'xxx' AND status = 1;

-- 创建覆盖索引（包含所有查询字段）
INDEX idx_tenant_status_cover (tenant_id, status, name, id);
```

**优势**：查询时不需要回表，直接从索引获取所有数据

#### 案例2：避免索引失效

```sql
-- ❌ 索引失效：对字段进行函数运算
SELECT * FROM users WHERE YEAR(created_at) = 2025;

-- ✅ 索引有效：使用范围查询
SELECT * FROM users WHERE created_at >= '2025-01-01' AND created_at < '2026-01-01';
```

#### 案例3：OR条件索引优化

```sql
-- ❌ 索引失效：OR条件
SELECT * FROM users WHERE email = 'xxx' OR username = 'yyy';

-- ✅ 使用UNION ALL
SELECT * FROM users WHERE email = 'xxx'
UNION ALL
SELECT * FROM users WHERE username = 'yyy';
```

### 5.1 主键约束

```sql
-- ✅ 方式1：自增主键（推荐用于内部ID）
id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',

-- ✅ 方式2：UUID主键（推荐用于分布式系统）

```

**主键选择建议**：
- 单机系统、内部ID：`BIGINT AUTO_INCREMENT`
- 分布式系统、对外ID：`VARCHAR(36) UUID` 或 `VARCHAR(64) 雪花ID
- 订单号、流水号：`VARCHAR(32)` 业务ID

### 5.2 唯一约束

```sql
-- ✅ 单字段唯一约束
UNIQUE KEY uk_email (email),

-- ✅ 复合唯一约束（租户级唯一）
UNIQUE KEY uk_tenant_email (tenant_id, email),
UNIQUE KEY uk_tenant_bot_name (tenant_id, name),

-- ✅ 带条件唯一约束（部分数据唯一）
UNIQUE KEY uk_tenant_username_active (tenant_id, username) WHERE deleted_at IS NULL,
```

**唯一约束命名**：`uk_{字段名}`

### 5.3 外键约束

```sql
-- ✅ 标准外键
FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,

-- ✅ 外键约束选项
ON DELETE CASCADE     -- 级联删除（删除主表记录时自动删除从表记录）
ON DELETE RESTRICT    -- 限制删除（有从表记录时禁止删除主表记录）
ON DELETE SET NULL    -- 置空（删除主表记录时将从表外键设为NULL）
ON DELETE NO ACTION   -- 无操作（默认，拒绝删除）
```

**外键设计建议**：
- ✅ 核心业务关系使用外键约束
- ✅ 级联删除：一对多关系的"多"方
- ✅ 限制删除：重要数据（防止误删）
- ❌ 高并发场景慎重使用外键（性能问题）

## 8. 性能优化规范

### 8.1 分区表设计

**适用于大数据量表**（如messages、logs、audit_logs）：

```sql
-- ✅ 按时间范围分区（推荐）
CREATE TABLE messages (
    id VARCHAR(64) NOT NULL,
    tenant_id VARCHAR(64) NOT NULL,
    conversation_id VARCHAR(64) NOT NULL,
    content TEXT,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id, created_at),
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_conversation_id (conversation_id)
) ENGINE=InnoDB
PARTITION BY RANGE (YEAR(created_at)) (
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION p2024 VALUES LESS THAN (2025),
    PARTITION p2025 VALUES LESS THAN (2026),
    PARTITION p2026 VALUES LESS THAN (2027),
    PARTITION p_future VALUES LESS THAN MAXVALUE
);
```

**分区建议**：
- 按时间分区：`created_at`（日志、消息）
- 按租户分区：`tenant_id`（租户数较少时）
- 按Hash分区：`id % N`（均匀分布）

### 8.2 垂直分区

**适用于超大规模表**（数据量>1亿行）：

```sql
-- ✅ 按租户ID Hash分区（8个分区）
CREATE TABLE conversations (
    id VARCHAR(64) NOT NULL,
    tenant_id VARCHAR(64) NOT NULL,
    -- ...
    PRIMARY KEY (id, tenant_id)
) ENGINE=InnoDB
PARTITION BY HASH(tenant_id)
PARTITIONS 8;
```

### 8.3 反范式化设计

**适度冗余，避免过度JOIN**：

```sql
-- ❌ 过度规范化（3次JOIN）
SELECT
    c.id,
    c.title,
    u.name AS user_name,
    b.name AS bot_name,
    b.avatar AS bot_avatar
FROM conversations c
JOIN users u ON c.user_id = u.id
JOIN bots b ON c.bot_id = b.id
WHERE c.tenant_id = 'xxx';

-- ✅ 适度冗余（减少JOIN）
ALTER TABLE conversations
ADD COLUMN user_name VARCHAR(100) COMMENT '用户姓名（冗余）',
ADD COLUMN bot_name VARCHAR(100) COMMENT 'Bot名称（冗余）',
ADD COLUMN bot_avatar VARCHAR(512) COMMENT 'Bot头像（冗余）';

-- 查询时无需JOIN
SELECT id, title, user_name, bot_name, bot_avatar
FROM conversations
WHERE tenant_id = 'xxx';
```

**反范式化原则**：
1. ✅ 读多写少的场景
2. ✅ 冗余字段更新频率低
3. ✅ 通过触发器或应用层维护一致性
4. ❌ 不滥用反范式化

### 8.4 计数器表

**避免实时计算COUNT(*)**：

```sql
-- ❌ 实时COUNT（性能差）
SELECT COUNT(*) FROM messages WHERE conversation_id = 'xxx';

-- ✅ 使用计数器表（性能好）
CREATE TABLE conversation_stats (
    conversation_id VARCHAR(64) PRIMARY KEY,
    message_count INT NOT NULL DEFAULT 0 COMMENT '消息数量',
    last_message_at DATETIME COMMENT '最后消息时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_last_message_at (last_message_at)
);

-- 更新计数器（通过触发器或应用层）
UPDATE conversation_stats
SET message_count = message_count + 1, last_message_at = NOW()
WHERE conversation_id = 'xxx';
```

## 13. 常见错误示例

### 13.1 命名错误

```sql
-- ❌ 错误1：使用驼峰命名
CREATE TABLE userInfo (  -- 应该是user_infos
    userId BIGINT,      -- 应该是user_id
    userName VARCHAR(50) -- 应该是user_name
);

-- ❌ 错误2：使用tb前缀
CREATE TABLE tb_user (  -- 不需要tb前缀
    id BIGINT
);

-- ❌ 错误3：使用保留字
CREATE TABLE order (  -- order是保留字
    id BIGINT
);
-- ✅ 正确
CREATE TABLE orders (
    id BIGINT
);
```

### 13.2 字段类型错误

```sql
-- ❌ 错误1：使用FLOAT存储金额
amount FLOAT NOT NULL DEFAULT 0.00 COMMENT '金额';
-- ✅ 正确
amount DECIMAL(18, 2) NOT NULL DEFAULT 0.00 COMMENT '金额（元）';

-- ❌ 错误2：VARCHAR长度过大
name VARCHAR(1000)  -- 最大255足够
-- ✅ 正确
name VARCHAR(100)

-- ❌ 错误3：使用TEXT存储索引字段
content TEXT NOT NULL
-- ✅ 正确
content TEXT NOT NULL,
FULLTEXT INDEX ft_content (content)
```

### 13.3 索引错误

```sql
-- ❌ 错误1：低选择性字段建索引
INDEX idx_gender (gender)  -- 只有2-3个值

-- ❌ 错误2：索引过多（5个以上）
INDEX idx_a (a),
INDEX idx_b (b),
INDEX idx_c (c),
INDEX idx_d (d),
INDEX idx_e (e),  -- 第5个索引
INDEX idx_f (f)   -- 第6个索引（过多）

-- ❌ 错误3：重复索引
INDEX idx_tenant_id (tenant_id),
UNIQUE KEY uk_tenant_bot_name (tenant_id, name)  -- tenant_id已在uk中
```
