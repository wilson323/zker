## 1. 实现概述

### 1.1 功能范围

组织中心是企业管理的核心功能，提供完整的组织架构管理能力，包括：

- ✅ **组织管理**：多级组织架构（公司→分公司→部门→项目组）
- ✅ **部门管理**：树形部门结构，支持移动和调整
- ✅ **岗位管理**：岗位定义、职级体系、职责描述
- ✅ **员工管理**：员工全生命周期管理（入职→在职→调岗→离职）
- ✅ **合同管理**：合同创建、签署、续签、终止
- ✅ **调岗管理**：调岗记录、审批流程
- ✅ **离职管理**：离职申请、审批、交接
- ✅ **企业通讯录**：多视图展示（部门视图、拼音视图）

## 4. 数据库设计亮点

### 4.1 闭包表（Closure Table）

**问题**: 如何高效查询组织树的所有子节点？

**传统方案**:
- **邻接表**（parent_id）：查询子树需要递归，性能差
- **路径枚举**：查询困难，更新复杂
- **嵌套集**：查询快，但插入/更新复杂

**闭包表方案**:
```sql
-- 闭包表存储所有节点间的路径关系
CREATE TABLE organization_trees (
    ancestor_id VARCHAR(36) NOT NULL,   -- 祖先节点
    descendant_id VARCHAR(36) NOT NULL, -- 后代节点
    depth INT NOT NULL                   -- 层级深度
);

-- 查询某个组织的所有子组织（包括自己）
SELECT o.*
FROM organizations o
JOIN organization_trees t ON o.org_id = t.descendant_id
WHERE t.ancestor_id = 'org123';

-- 查询某个组织的所有父组织（路径）
SELECT o.*
FROM organizations o
JOIN organization_trees t ON o.org_id = t.ancestor_id
WHERE t.descendant_id = 'org456' AND t.depth > 0
ORDER BY t.depth ASC;
```

**优势**:
- ✅ 查询子树：O(1)复杂度
- ✅ 查询路径：O(1)复杂度
- ✅ 插入节点：批量插入路径，效率高
- ✅ 移动子树：删除旧路径，创建新路径
- ✅ 无递归查询，性能优秀

### 4.2 索引优化策略

**覆盖索引**:
```sql
-- 员工表的多列索引
CREATE INDEX idx_dept_status ON employees(dept_id, status, hire_date);

-- 查询可以直接使用索引，无需回表
SELECT * FROM employees
WHERE dept_id = 'dept123' AND status = 'active'
ORDER BY hire_date DESC;
```

**最左前缀原则**:
```sql
-- 复合索引：(tenant_id, dept_id, status)
-- 可以支持：
WHERE tenant_id = ?
WHERE tenant_id = ? AND dept_id = ?
WHERE tenant_id = ? AND dept_id = ? AND status = ?
```

### 4.3 软删除设计

```sql
-- 所有表使用 deleted_at 软删除
deleted_at BIGINT DEFAULT NULL,

-- 查询时过滤
SELECT * FROM organizations WHERE deleted_at IS NULL;

-- 索引
CREATE INDEX idx_deleted_at ON organizations(deleted_at);
```

**优势**:
- ✅ 数据可恢复
- ✅ 审计追踪
- ✅ 关联数据完整性

## 5. 技术决策记录

### 5.1 为什么使用闭包表而不是邻接表？

**决策**: 使用闭包表（Closure Table）

**原因**:
1. **查询性能**：子树查询O(1)，无需递归
2. **维护简单**：插入/移动逻辑清晰
3. **扩展性好**：支持任意层级深度
4. **成熟方案**：业界广泛使用（如WordPress、Magento）

**代价**:
- 存储空间：O(n²)，但现代数据库可接受
- 插入性能：需要批量插入路径，可接受

### 5.2 为什么员工不直接存储在部门下？

**决策**: 员工属于组织（org），而非部门（dept）

**原因**:
1. **灵活性**：员工可以调动，但组织归属不变
2. **权限控制**：基于组织的权限更清晰
3. **业务逻辑**：员工入职是入职公司，而非入职部门

### 5.3 为什么使用BIGINT存储时间戳？

**决策**: 使用毫秒级BIGINT时间戳

**原因**:
1. **精度**：毫秒级精度满足业务需求
2. **跨时区**：UTC时间戳，避免时区问题
3. **性能**：整数比较比DATETIME快
4. **兼容性**：Go/JavaScript都支持毫秒时间戳
