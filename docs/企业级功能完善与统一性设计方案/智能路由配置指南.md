# 智能路由配置指南

## 概述

ZKER 智能路由引擎基于**混合意图匹配**和**多因子评分**，能够根据用户输入自动路由到最合适的Bot或工作流。

## 核心概念

### 1. 路由规则类型

- **keyword**: 关键词匹配
- **regex**: 正则表达式匹配
- **intent**: 意图匹配（基于NLP）
- **category**: 分类匹配

### 2. 意图匹配策略

- **规则匹配**: 基于预定义规则
- **相似度匹配**: 基于向量嵌入的语义匹配
- **模型匹配**: 基于ML模型的意图识别

### 3. 路由评分因子

| 因子 | 权重 | 说明 |
|------|------|------|
| 意图匹配 | 30% | 匹配置信度 |
| 服务健康度 | 20% | Bot/工作流成功率 |
| 当前负载 | 20% | Bot/工作流负载情况 |
| 区域亲和性 | 10% | 用户与Bot的区域匹配 |
| 成本 | 10% | 调用成本 |

## API 使用指南

### 1. 路由规则管理

#### 1.1 创建路由规则

**接口**: `POST /routing/rules`

**请求参数**:
```json
{
  "tenant_id": "tenant_abc123",
  "rule_name": "客服咨询路由",
  "rule_type": "keyword",
  "priority": 100,
  "condition": "{\"keywords\":[\"客服\",\"咨询\",\"帮助\"]}",
  "target_bot_id": "bot_customer_service",
  "target_workflow_id": null,
  "is_active": true
}
```

**字段说明**:
- `rule_type`: 规则类型（keyword/regex/intent/category）
- `priority`: 优先级（数字越大优先级越高，0-1000）
- `condition`: 匹配条件（JSON格式）

**响应示例**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "rule_id": "rule_abc123",
    "rule_name": "客服咨询路由",
    "priority": 100,
    "created_at": 1704067200000
  }
}
```

#### 1.2 更新路由规则

**接口**: `PUT /routing/rules/{rule_id}`

**请求参数**:
```json
{
  "rule_name": "客服咨询路由（更新）",
  "priority": 150,
  "is_active": true
}
```

#### 1.3 删除路由规则

**接口**: `DELETE /routing/rules/{rule_id}`

#### 1.4 列出路由规则

**接口**: `GET /routing/rules`

**查询参数**:
- `tenant_id`: 租户ID（必填）
- `rule_type`: 规则类型（可选）
- `is_active`: 是否启用（可选）
- `page_size`: 每页数量（可选，默认20）

**响应示例**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "rules": [
      {
        "rule_id": "rule_abc123",
        "rule_name": "客服咨询路由",
        "rule_type": "keyword",
        "priority": 100,
        "is_active": true
      }
    ],
    "total_count": 10
  }
}
```

### 2. 路由决策

#### 2.1 执行路由

**接口**: `POST /routing/route`

**请求参数**:
```json
{
  "user_input": "我需要客服帮助",
  "tenant_id": "tenant_abc123",
  "context": {
    "user_id": "user_123",
    "channel": "web",
    "region": "cn-north"
  }
}
```

**响应示例**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "bot_id": "bot_customer_service",
    "workflow_id": null,
    "confidence": 0.92,
    "score": 0.85,
    "reasons": [
      "Intent: 0.28",
      "Health: 0.19",
      "Load: 0.18",
      "Region: 0.10",
      "Cost: 0.10"
    ],
    "match_type": "keyword",
    "rule_id": "rule_abc123"
  }
}
```

**字段说明**:
- `confidence`: 意图匹配置信度（0-1）
- `score": 综合评分（0-1）
- `reasons`: 各因子得分说明

**查询参数**:

**响应示例**:

      {
        "log_id": "log_xyz789",

## 混合意图匹配配置

### 配置混合匹配器权重

**接口**: `POST /routing/matcher/weights`

**请求参数**:
```json
{
  "rule_weight": 0.5,
  "similarity_weight": 0.3,
  "model_weight": 0.2
}
```

**说明**:
- `rule_weight`: 规则匹配权重（建议0.3-0.6）
- `similarity_weight`: 相似度匹配权重（建议0.2-0.5）
- `model_weight`: 模型匹配权重（建议0.1-0.3）

### 配置评分权重

**接口**: `POST /routing/scorer/weights`

**请求参数**:
```json
{
  "intent_weight": 0.3,
  "health_weight": 0.2,
  "load_weight": 0.2,
  "cost_weight": 0.1,
  "region_weight": 0.1
}
```

## 相似度匹配配置

### 为Bot启用相似度匹配

**步骤**:

1. 为Bot生成向量嵌入
2. 设置相似度阈值（建议0.7-0.9）

**接口**: `POST /bots/{bot_id}/embedding`

**请求参数**:
```json
{
  "description": "这是一个客服Bot，可以处理用户咨询、订单查询、售后问题"
}
```

**说明**: 系统会自动生成向量嵌入并存储。

### 设置相似度阈值

**接口**: `POST /routing/similarity/threshold`

**请求参数**:
```json
{
  "threshold": 0.75
}
```

**建议值**:
- 精确匹配: 0.85-0.95
- 一般匹配: 0.70-0.85
- 宽松匹配: 0.60-0.70

## 高级配置

### 1. 服务健康检查

**接口**: `POST /routing/health/check`

**请求参数**:
```json
{
  "bot_id": "bot_customer_service",
  "check_type": "success_rate",
  "window_minutes": 5
}
```

**响应示例**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "bot_id": "bot_customer_service",
    "is_healthy": true,
    "success_rate": 0.95,
    "avg_latency_ms": 150,
    "current_load": 25,
    "max_capacity": 100
  }
}
```

### 2. 负载均衡配置

**接口**: `POST /routing/load-balance/config`

**请求参数**:
```json
{
  "strategy": "least_loaded",
  "max_load_percent": 80
}
```

**策略说明**:
- `least_loaded`: 选择负载最低的
- `round_robin`: 轮询
- `random`: 随机

### 3. 熔断配置

**接口**: `POST /routing/circuit-breaker/config`

**请求参数**:
```json
{
  "failure_threshold": 5,
  "success_threshold": 2,
  "timeout_seconds": 30,
  "half_open_max_calls": 3
}
```

**参数说明**:
- `failure_threshold`: 失败阈值（连续失败多少次后熔断）
- `success_threshold`: 成功阈值（半开状态需要多少次成功后恢复）
- `timeout_seconds`: 熔断超时时间
- `half_open_max_calls`: 半开状态最大调用次数

## 使用场景示例

### 场景1: 智能客服路由

**需求**: 根据用户咨询内容自动路由到对应的Bot（客服、技术支持、投诉处理）。

**配置步骤**:

1. 创建三个Bot：
   - `bot_customer_service`: 通用客服
   - `bot_tech_support`: 技术支持
   - `bot_complaint`: 投诉处理

2. 配置路由规则：

```bash
# 客服规则
curl -X POST https://api.zker.com/v1/routing/rules \
  -d '{
    "rule_name": "客服咨询",
    "rule_type": "keyword",
    "priority": 100,
    "condition": {"keywords": ["客服", "咨询", "帮助"]},
    "target_bot_id": "bot_customer_service"
  }'

# 技术支持规则
curl -X POST https://api.zker.com/v1/routing/rules \
  -d '{
    "rule_name": "技术支持",
    "rule_type": "keyword",
    "priority": 100,
    "condition": {"keywords": ["技术", "bug", "故障", "无法使用"]},
    "target_bot_id": "bot_tech_support"
  }'

# 投诉处理规则
curl -X POST https://api.zker.com/v1/routing/rules \
  -d '{
    "rule_name": "投诉处理",
    "rule_type": "keyword",
    "priority": 120,
    "condition": {"keywords": ["投诉", "不满", "差评"]},
    "target_bot_id": "bot_complaint"
  }'
```

3. 执行路由：

```bash
curl -X POST https://api.zker.com/v1/routing/route \
  -d '{
    "user_input": "我的账号无法登录了",
    "tenant_id": "tenant_abc123"
  }'
```

**响应**:
```json
{
  "code": 0,
  "data": {
    "bot_id": "bot_tech_support",
    "confidence": 0.85,
    "score": 0.82,
    "reasons": ["匹配到技术支持规则"]
  }
}
```

### 场景2: 相似度语义匹配

**需求**: 用户输入"怎么退货？"应路由到退换货Bot，即使没有完全匹配的关键词。

  -d '{"threshold": 0.75}'

3. 执行路由：

```bash
curl -X POST https://api.zker.com/v1/routing/route \
  -d '{
    "user_input": "怎么退货？",
    "tenant_id": "tenant_abc123"
  }'
```

**响应**:
```json
{
  "code": 0,
  "data": {
    "bot_id": "bot_return_refund",
    "confidence": 0.82,
    "match_type": "similarity"
  }

```

## 性能优化建议

### 1. 规则优先级设计

- ✅ 高优先级规则（100-200）：精确匹配、VIP用户、投诉处理
- ✅ 中优先级规则（50-99）：常见业务场景
- ✅ 低优先级规则（1-49）：兜底规则、通用Bot

### 2. 相似度匹配优化

- ✅ 使用合适的阈值（过高导致匹配失败，过低导致误匹配）
- ✅ 定期更新Bot的向量嵌入（当Bot功能变化时）
- ✅ 使用缓存存储向量嵌入

### 3. 评分权重调整

根据业务场景调整权重：

| 场景 | 意图 | 健康 | 负载 | 区域 | 成本 |
|------|------|------|------|------|------|
| 追求准确性 | 40% | 20% | 10% | 10% | 10% |
| 追求可用性 | 20% | 30% | 30% | 10% | 10% |
| 追求低成本 | 20% | 10% | 10% | 10% | 50% |

### 4. 熔断保护

- ✅ 为关键Bot配置熔断保护
- ✅ 设置合理的失败阈值（建议3-10次）
- ✅ 定期检查熔断状态

## 附录

### A. 路由规则最佳实践

1. **避免规则冲突**: 相似输入应设置不同优先级
2. **定期审查规则**: 删除过时规则，更新现有规则
3. **使用测试工具**: 配置后使用模拟输入测试路由效果
4. **监控路由效果**: 关注成功率和响应延迟

### B. 常见问题

**Q: 为什么路由到了错误的Bot？**
A: 检查规则优先级、匹配条件配置，查看路由日志。

**Q: 如何提高相似度匹配准确度？**
A: 优化Bot描述文本，调整相似度阈值，使用更多训练数据。

**Q: Bot不健康怎么办？**
A: 检查Bot日志，重启Bot实例，配置熔断保护。
