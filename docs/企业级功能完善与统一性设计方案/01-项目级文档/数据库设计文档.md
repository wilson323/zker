## 1. 数据库概述

### 1.1 数据库选型

**主数据库**: MySQL 8.4.5

**选型理由**:
- ✅ 成熟稳定,生态完善
- ✅ 支持事务,数据一致性强
- ✅ 支持JSON字段,灵活性高
- ✅ 团队熟悉度高
- ✅ zker已有MySQL基础

**适用场景**:
- 主数据存储 (租户、用户、Bot、对话等)
- 需要事务支持的场景
- 关系型数据查询

### 1.3 数据库命名规范

#### 1.3.1 表命名

- 全部小写
- 使用下划线分隔
- 使用复数形式
- 示例: `users`, `bot_skills`, `conversation_messages`

#### 1.3.2 字段命名

- 全部小写
- 使用下划线分隔
- 示例: `tenant_id`, `created_at`, `is_deleted`

#### 1.3.3 索引命名

- 普通索引: `idx_字段名`
  - 示例: `idx_tenant_id`, `idx_email`
- 唯一索引: `uk_字段名`
  - 示例: `uk_tenant_email`, `uk_username`
- 全文索引: `ft_字段名`
  - 示例: `ft_content`

### 2.2 实体定义

#### 2.2.1 租户 (Tenant)

```sql
CREATE TABLE tenants (
    id VARCHAR(64) PRIMARY KEY COMMENT '租户ID',
    company_name VARCHAR(255) NOT NULL UNIQUE COMMENT '企业名称',
    subdomain VARCHAR(63) NOT NULL UNIQUE COMMENT '子域名',
    contact_name VARCHAR(100) NOT NULL COMMENT '联系人姓名',
    contact_email VARCHAR(255) NOT NULL COMMENT '联系人邮箱',
    contact_phone VARCHAR(20) NOT NULL COMMENT '联系人电话',
    employee_count INT NOT NULL COMMENT '员工数量',
    industry VARCHAR(100) NOT NULL COMMENT '行业',
    deployment_type ENUM('public', 'private') NOT NULL COMMENT '部署方式',
    status ENUM('active', 'suspended', 'deleted') NOT NULL DEFAULT 'active' COMMENT '状态',
    trial_start_date DATETIME COMMENT '试用开始日期',
    trial_end_date DATETIME COMMENT '试用结束日期',
    quota JSON COMMENT '配额信息',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_status (status),
    INDEX idx_trial_end_date (trial_end_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='租户表';
```

#### 2.2.2 用户 (User)

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
    email VARCHAR(255) NOT NULL COMMENT '邮箱',
    username VARCHAR(50) NOT NULL COMMENT '用户名',
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
    name VARCHAR(100) NOT NULL COMMENT '姓名',
    phone VARCHAR(20) COMMENT '手机号',
    department_id BIGINT COMMENT '部门ID',
    position_id BIGINT COMMENT '岗位ID',
    avatar VARCHAR(512) COMMENT '头像URL',
    status ENUM('active', 'inactive') NOT NULL DEFAULT 'active' COMMENT '状态',
    mfa_enabled BOOLEAN NOT NULL DEFAULT FALSE COMMENT '是否启用MFA',
    mfa_secret VARCHAR(32) COMMENT 'MFA密钥',
    last_login_at DATETIME COMMENT '最后登录时间',
    last_login_ip VARCHAR(45) COMMENT '最后登录IP',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_tenant_email (tenant_id, email),
    UNIQUE KEY uk_tenant_username (tenant_id, username),
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_department_id (department_id),
    INDEX idx_status (status),
    FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

#### 2.2.3 Bot

```sql
CREATE TABLE bots (
    id VARCHAR(64) PRIMARY KEY COMMENT 'Bot ID',
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
    creator_id BIGINT NOT NULL COMMENT '创建者ID',
    name VARCHAR(100) NOT NULL COMMENT 'Bot名称',
    description VARCHAR(500) COMMENT 'Bot描述',
    avatar VARCHAR(512) COMMENT 'Bot头像URL',
    prompt TEXT COMMENT '系统提示词',
    conversation_style JSON COMMENT '对话风格',
    status ENUM('draft', 'published', 'archived') NOT NULL DEFAULT 'draft' COMMENT '状态',
    published_at DATETIME COMMENT '发布时间',
    published_by BIGINT COMMENT '发布者ID',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_tenant_name (tenant_id, name),
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_status (status),
    INDEX idx_creator_id (creator_id),
    FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,
    FOREIGN KEY (creator_id) REFERENCES users(id),
    FOREIGN KEY (published_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Bot表';
```

#### 2.2.4 会话 (Conversation)

```sql
CREATE TABLE conversations (
    id VARCHAR(64) PRIMARY KEY COMMENT '会话ID',
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    bot_id VARCHAR(64) NOT NULL COMMENT 'Bot ID',
    title VARCHAR(255) COMMENT '会话标题',
    status ENUM('active', 'archived') NOT NULL DEFAULT 'active' COMMENT '状态',
    message_count INT NOT NULL DEFAULT 0 COMMENT '消息数量',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_user_id (user_id),
    INDEX idx_bot_id (bot_id),
    INDEX idx_status (status),
    INDEX idx_updated_at (updated_at),
    FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (bot_id) REFERENCES bots(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='会话表';
```

#### 2.2.5 消息 (Message)

```sql
CREATE TABLE messages (
    id VARCHAR(64) PRIMARY KEY COMMENT '消息ID',
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
    conversation_id VARCHAR(64) NOT NULL COMMENT '会话ID',
    role ENUM('user', 'bot', 'system') NOT NULL COMMENT '角色',
    content TEXT NOT NULL COMMENT '消息内容',
    message_type ENUM('text', 'image', 'file') NOT NULL DEFAULT 'text' COMMENT '消息类型',
    file_url VARCHAR(512) COMMENT '文件URL',
    metadata JSON COMMENT '元数据',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_conversation_id (conversation_id),
    INDEX idx_created_at (created_at),
    FULLTEXT INDEX ft_content (content) WITH PARSER ngram,
    FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,
    FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='消息表';
```

#### 2.2.6 知识库 (KnowledgeBase)

```sql
CREATE TABLE knowledge_bases (
    id VARCHAR(64) PRIMARY KEY COMMENT '知识库ID',
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
    creator_id BIGINT NOT NULL COMMENT '创建者ID',
    name VARCHAR(100) NOT NULL COMMENT '知识库名称',
    description VARCHAR(500) COMMENT '描述',
    document_count INT NOT NULL DEFAULT 0 COMMENT '文档数量',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_tenant_name (tenant_id, name),
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_creator_id (creator_id),
    FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,
    FOREIGN KEY (creator_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识库表';
```

#### 2.2.7 知识文档 (Document)

```sql
CREATE TABLE documents (
    id VARCHAR(64) PRIMARY KEY COMMENT '文档ID',
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',
    knowledge_base_id VARCHAR(64) NOT NULL COMMENT '知识库ID',
    file_name VARCHAR(255) NOT NULL COMMENT '文件名',
    file_size BIGINT NOT NULL COMMENT '文件大小(字节)',
    file_type VARCHAR(10) NOT NULL COMMENT '文件类型',
    file_url VARCHAR(512) NOT NULL COMMENT '文件URL',
    chunk_count INT COMMENT '分块数量',
    status ENUM('processing', 'ready', 'failed') NOT NULL DEFAULT 'processing' COMMENT '状态',
    uploaded_by BIGINT NOT NULL COMMENT '上传者ID',
    processed_at DATETIME COMMENT '处理完成时间',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_knowledge_base_id (knowledge_base_id),
    INDEX idx_status (status),
    INDEX idx_uploaded_by (uploaded_by),
    FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE,
    FOREIGN KEY (knowledge_base_id) REFERENCES knowledge_bases(id) ON DELETE CASCADE,
    FOREIGN KEY (uploaded_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识文档表';
```

## 4. 索引设计

### 4.1 索引策略

#### 4.1.1 索引类型

| 索引类型 | 用途 | 示例 |
|---------|------|------|
| **主键索引** | 唯一标识,聚簇索引 | PRIMARY KEY (id) |
| **唯一索引** | 保证数据唯一性 | UNIQUE KEY uk_email (email) |
| **普通索引** | 加速查询 | INDEX idx_tenant_id (tenant_id) |
| **复合索引** | 多字段查询 | INDEX idx_tenant_status (tenant_id, status) |
| **全文索引** | 全文搜索 | FULLTEXT INDEX ft_content (content) |

#### 4.1.2 索引设计原则

**最左前缀原则**:
```sql
-- 复合索引 (tenant_id, status, created_at)
-- 可以使用:
WHERE tenant_id = ?
WHERE tenant_id = ? AND status = ?
WHERE tenant_id = ? AND status = ? AND created_at > ?

-- 不能使用:
WHERE status = ?
WHERE created_at > ?
```

**选择性原则**:
- 高选择性字段优先建索引 (如: email, username)
- 低选择性字段不单独建索引 (如: gender, status)

**覆盖索引**:
```sql
-- 覆盖索引 (user_id, bot_id, title, updated_at)
-- 查询时不需要回表:
SELECT title, updated_at FROM conversations WHERE user_id = ? AND bot_id = ?
```

### 4.2 核心表索引

#### 4.2.1 users表索引

```sql
-- 主键索引
PRIMARY KEY (id)

-- 唯一索引
UNIQUE KEY uk_tenant_email (tenant_id, email)
UNIQUE KEY uk_tenant_username (tenant_id, username)

-- 普通索引
INDEX idx_tenant_id (tenant_id)
INDEX idx_status (status)
INDEX idx_created_at (created_at)

-- 复合索引
INDEX idx_tenant_status (tenant_id, status)
INDEX idx_tenant_created (tenant_id, created_at)
```

#### 4.2.2 conversations表索引

```sql
-- 主键索引
PRIMARY KEY (id)

-- 普通索引
INDEX idx_tenant_id (tenant_id)
INDEX idx_user_id (user_id)
INDEX idx_bot_id (bot_id)
INDEX idx_status (status)
INDEX idx_updated_at (updated_at)

-- 复合索引
INDEX idx_user_updated (user_id, updated_at)
INDEX idx_tenant_status (tenant_id, status)

-- 覆盖索引
INDEX idx_conversation_list (user_id, bot_id, title, updated_at, status)
```

#### 4.2.3 messages表索引

```sql
-- 主键索引
PRIMARY KEY (id)

-- 普通索引
INDEX idx_tenant_id (tenant_id)
INDEX idx_conversation_id (conversation_id)
INDEX idx_created_at (created_at)

-- 复合索引
INDEX idx_conversation_created (conversation_id, created_at)

-- 全文索引
FULLTEXT INDEX ft_content (content) WITH PARSER ngram
```

### 4.3 索引优化建议

#### 4.3.1 避免过度索引

**反例**:
```sql
-- 不推荐: 为每个字段都建索引
CREATE TABLE users (
    ...
    INDEX idx_name (name),
    INDEX idx_phone (phone),
    INDEX idx_address (address),
    INDEX idx_city (city),
    INDEX idx_province (province),
    ...
);
```

**正例**:
```sql
-- 推荐: 只为高频查询字段建索引
CREATE TABLE users (
    ...
    INDEX idx_tenant_email (tenant_id, email),
    INDEX idx_tenant_status (tenant_id, status),
);
```

#### 4.3.2 定期分析索引

```sql
-- 查看未使用的索引
SELECT
    object_name,
    index_name,
    count_read,
    count_write
FROM mysql.innodb_index_stats
WHERE database_name = 'saas'
  AND count_read = 0
  AND count_write > 0
ORDER BY count_write DESC;

-- 删除未使用的索引
DROP INDEX idx_unused ON users;
```

## 5. 分库分表设计

### 5.1 分片策略

#### 5.1.1 水平分片 (Sharding)

**按租户ID分片**:
```go
// 分片算法
func getShardID(tenantID string) int {
    hash := crc32.ChecksumIEEE([]byte(tenantID))
    return int(hash % 10) // 10个分片
}

// 获取分片数据库
func getDB(tenantID string) *gorm.DB {
    shardID := getShardID(tenantID)
    return dbs[shardID]
}
```

**分片配置**:
```
Shard 0: saas_shard_0 (tenant_id hash % 10 = 0)
Shard 1: saas_shard_1 (tenant_id hash % 10 = 1)
...
Shard 9: saas_shard_9 (tenant_id hash % 10 = 9)
```

#### 5.1.2 垂直分片

**按业务领域分片**:
```
Shard 0: tenants, users (租户和用户)
Shard 1: bots, bot_skills (Bot相关)
Shard 2: conversations, messages (对话相关)
Shard 3: knowledge_bases, documents (知识库相关)
Shard 4: billing_records, invoices (计费相关)
```

### 5.2 分表策略

#### 5.2.1 按时间分表

**messages表按月分表**:
```sql
-- 2025年1月的消息表
CREATE TABLE messages_202501 (
    ...
) PARTITION BY RANGE (TO_DAYS(created_at)) (
    PARTITION p20250101 VALUES LESS THAN (TO_DAYS('2025-01-02')),
    PARTITION p20250102 VALUES LESS THAN (TO_DAYS('2025-01-03')),
    ...
);

-- 或使用分表
CREATE TABLE messages_202501 LIKE messages;
CREATE TABLE messages_202502 LIKE messages;
...
```

**查询路由**:
```go
func getMessagesTable(date time.Time) string {
    return fmt.Sprintf("messages_%s", date.Format("200601"))
}

// 查询时动态选择表

```

#### 5.2.2 按ID范围分表

**conversations表按ID范围分表**:
```
conversations_0: id [0, 1000000)
conversations_1: id [1000000, 2000000)
conversations_2: id [2000000, 3000000)
...
```

### 5.3 分库分表中间件

#### 5.3.1 ShardingSphere

**配置示例**:
```yaml
sharding:
  tables:
    messages:
      actualDataNodes: ds_${0..1}.messages_${0..11}
      databaseStrategy:
        standard:
          shardingColumn: tenant_id
          shardingAlgorithmName: tenant_db_mod
      tableStrategy:
        standard:
          shardingColumn: created_at
          shardingAlgorithmName: message_time_interval

  shardingAlgorithms:
    tenant_db_mod:
      type: MOD
      props:
        sharding-count: 2
    message_time_interval:
      type: INTERVAL
      props:
        datetime-pattern: yyyy-MM
        datetime-lower: 2025-01
        datetime-upper: 2025-12
        sharding-suffix-pattern: yyyyMM
```

#### 5.3.2 自研路由层

```go
type ShardRouter struct {
    dbs []*gorm.DB
}

func (r *ShardRouter) Route(tenantID string, table string) *gorm.DB {
    shardID := getShardID(tenantID)
    return r.dbs[shardID].Table(table)
}

// 使用
router := NewShardRouter(dbs)
db := router.Route("tenant-a", "users")
db.Where("id = ?", 123).First(&user)
```
