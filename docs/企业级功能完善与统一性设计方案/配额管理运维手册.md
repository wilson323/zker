# 配额管理运维手册

## 概述

本文档面向运维工程师和SRE团队，详细说明ZKER企业级配额管理系统的运维操作、监控告警、故障排查等。

## 1. 系统架构

### 1.1 核心组件

```
┌─────────────────────────────────────────────────────┐
│                   应用层                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────┐  │
│  │  Bot Service │  │  Chat Service│  │  ...     │  │
│  └──────┬───────┘  └──────┬───────┘  └─────┬────┘  │
│         │                 │                │         │
└─────────┼─────────────────┼────────────────┼─────────┘
          │                 │                │
┌─────────┼─────────────────┼────────────────┼─────────┐
│         ▼                 ▼                ▼         │
│  ┌──────────────────────────────────────────────┐  │
│  │         Quota Service (配额服务)            │  │
│  │  - CheckQuota()    检查配额                │  │
│  │  - ConsumeQuota()  消费配额                │  │
│  │  - RollbackQuota() 回滚配额                │  │
│  └───────────────────┬──────────────────────────┘  │
│                      ▼                             │
│  ┌──────────────────────────────────────────────┐  │
│  │      Quota Monitor (配额监控服务)           │  │
│  │  - MonitorQuotas()   监控配额               │  │
│  │  - ResetQuotas()     重置到期配额            │  │
│  │  - SendAlert()       发送告警               │  │
│  └───────────────────┬──────────────────────────┘  │
└──────────────────────┼──────────────────────────────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   ┌─────────┐  ┌──────────┐  ┌──────────┐
   │ MySQL   │  │  Redis   │  │ Alerts   │
   │(持久化) │  │  (缓存)  │  │ (告警)   │
   └─────────┘  └──────────┘  └──────────┘
```

### 1.2 数据流

#### 配额检查流程
```
1. 业务请求 → QuotaService.CheckQuota()
2. 查询Redis缓存 → 命中？
   - 是 → 返回配额信息
   - 否 → 查询MySQL → 写入Redis
3. 判断配额是否充足
   - 是 → 允许业务执行
   - 否 → 返回QUOTA_EXCEEDED错误
```

#### 配额消费流程
```
1. 业务执行成功 → QuotaService.ConsumeQuota()
2. 查询配额信息
3. 更新数据库 (UPDATE quotas SET used_count = used_count + N)
4. 删除Redis缓存 (强制下次重新查询)
5. 返回成功
```

#### 配额监控流程
```
定时任务 (每5分钟)
  ↓
QuotaMonitor.MonitorQuotas()
  ↓
遍历所有配额
  ↓
检查使用率
  ├─ ≥ 80%  → warning告警
  ├─ ≥ 95%  → critical告警
  └─ ≥ 100% → exceeded告警
```

## 2. 部署配置

### 2.1 环境变量

```bash
# Quota Service配置
QUOTA_SERVICE_ENABLED=true
QUOTA_CHECK_STRICT=true  # 严格模式：配额不足直接拒绝
QUOTA_CACHE_ENABLED=true
QUOTA_CACHE_TTL=300     # 缓存过期时间（秒）

# Quota Monitor配置
QUOTA_MONITOR_ENABLED=true
QUOTA_MONITOR_INTERVAL=300  # 监控间隔（秒）
QUOTA_ALERT_ENABLED=true
QUOTA_RESET_ENABLED=true

# 告警配置
ALERT_WEBHOOK_URL=https://hooks.example.com/alerts
ALERT_EMAIL_RECIPIENTS=ops@example.com,sre@example.com
ALERT_SMS_RECIPIENTS=+86-13800138000

# 阈值配置
QUOTA_WARNING_THRESHOLD=80   # 警告阈值（百分比）
QUOTA_CRITICAL_THRESHOLD=95  # 严重阈值（百分比）
```

### 2.2 数据库配置

```sql
-- 配额表索引
CREATE INDEX idx_tenant_resource ON quotas(tenant_id, resource_type);

    PARTITION p202401 VALUES LESS THAN ('2024-02-01'),
    PARTITION p202402 VALUES LESS THAN ('2024-03-01'),
    ...
);
```

```redis
# 最大内存
maxmemory 2gb

# 淘汰策略
maxmemory-policy allkeys-lru
```

## 4. 告警配置

### 4.1 告警规则

#### 配额超限告警

```yaml
# alerting_rules.yml
groups:
  - name: quota_alerts
    interval: 30s
    rules:
      # 警告级别
      - alert: QuotaWarning
        expr: quota_usage_percent >= 80
        for: 5m
        labels:
          severity: warning
          tenant_id: "{{ $labels.tenant_id }}"
          resource_type: "{{ $labels.resource_type }}"
        annotations:
          summary: "租户 {{ $labels.tenant_id }} 资源 {{ $labels.resource_type }} 使用率达 {{ $value }}%"
          description: "当前使用量 {{ $labels.used_count }} / {{ $labels.max_limit }}"

      # 严重级别
      - alert: QuotaCritical
        expr: quota_usage_percent >= 95
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "配额使用率严重告警"

      # 超限级别
      - alert: QuotaExceeded
        expr: quota_usage_percent >= 100
        for: 1m
        labels:
          severity: emergency
        annotations:
          summary: "配额已超限，需立即处理！"
```

#### 性能告警

```yaml
  - name: performance_alerts
    interval: 30s
    rules:
      - alert: QuotaCheckHighLatency
        expr: histogram_quantile(0.99, rate(quota_check_latency_seconds_bucket[5m])) > 0.1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "配额检查延迟P99超过100ms"

      - alert: RedisCacheLowHitRate
        expr: redis_cache_hit_rate < 0.8
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "Redis缓存命中率低于80%"
```

## 5. 日常运维

### 5.1 配额调整

#### 增加配额

```sql
-- 1. 查询当前配额
SELECT * FROM quotas
WHERE tenant_id = 'tenant_abc123'
  AND resource_type = 'bots';

-- 2. 更新配额限制
UPDATE quotas
SET max_limit = 200,
    updated_at = UNIX_TIMESTAMP() * 1000
WHERE tenant_id = 'tenant_abc123'
  AND resource_type = 'bots';

-- 3. 清除缓存
DEL tenant:tenant_abc123:quota:bots
```

#### 重置配额

```sql
-- 重置使用量为0
UPDATE quotas
SET used_count = 0,
    last_reset_at = UNIX_TIMESTAMP() * 1000,
    updated_at = UNIX_TIMESTAMP() * 1000
WHERE quota_id = 'quota_xyz789';

-- 清除缓存
DEL tenant:tenant_abc123:quota:*
```

### 5.2 手动执行配额重置

```bash
# 调用API
curl -X POST http://quota-monitor:8081/reset \
  -H "Content-Type: application/json" \
  -d '{
    "dry_run": false,
    "tenant_ids": ["tenant_abc123", "tenant_def456"]
  }'
```

### 5.3 查询配额状态

```bash
# 查询所有租户配额
curl -X GET "http://quota-service:8080/quotas?status=exceeded"

# 查询指定租户配额
curl -X GET "http://quota-service:8080/tenants/tenant_abc123/quotas"

# 查询配额使用率TOP10
curl -X GET "http://quota-service:8080/quotas/top?limit=10"
```

## 6. 故障排查

### 6.1 常见问题

#### 问题1: 配额检查慢

**现象**: 配额检查延迟超过100ms

**排查步骤**:
1. 检查Redis缓存命中率
```bash
redis-cli info stats | grep keyspace_hits
```

2. 检查MySQL慢查询
```sql
SELECT * FROM mysql.slow_log
WHERE sql_text LIKE '%quotas%'
ORDER BY query_time DESC
LIMIT 10;
```

3. 检查应用日志
```bash
grep "quota_check_latency" /var/log/quota-service/app.log | tail -100
```

**解决方案**:
- 增加Redis缓存TTL
- 优化MySQL索引
- 增加应用实例数

#### 问题2: 配额超限告警未收到

**现象**: 配额已超限，但未收到告警

**排查步骤**:
1. 检查监控服务状态
```bash
curl http://quota-monitor:8081/health
```

2. 检查告警配置
```bash
curl http://alertmanager:9093/api/v1/alerts
```

3. 检查通知渠道
```bash
# 测试邮件通知
echo "Test" | mail -s "Test Alert" ops@example.com

# 测试企业微信通知
curl -X POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx \
  -d '{"msgtype":"text","text":{"content":"Test Alert"}}'
```

**解决方案**:
- 重启监控服务
- 更新告警配置
- 检查通知渠道配置

#### 问题3: 配额数据不一致

**现象**: Redis缓存与MySQL数据不一致

**排查步骤**:
1. 对比数据
```bash
# Redis中的配额
redis-cli GET "tenant:tenant_abc123:quota:bots"

# MySQL中的配额
mysql> SELECT used_count, max_limit FROM quotas
       WHERE tenant_id = 'tenant_abc123' AND resource_type = 'bots';
```

2. 检查缓存写入逻辑
```bash
grep "cache.Set" /var/log/quota-service/app.log | tail -50
```

**解决方案**:
```bash
# 清除不一致的缓存
redis-cli DEL "tenant:tenant_abc123:quota:bots"

# 重启应用
kubectl rollout restart deployment/quota-service
```

### 6.2 紧急处理流程

#### 配额误报超限

**现象**: 用户实际未超限，但被拒绝访问

**处理步骤**:
1. 确认实际使用量
```sql
SELECT * FROM quotas
WHERE tenant_id = 'tenant_abc123'
  AND resource_type = 'bots';
```

2. 检查是否有并发问题
```bash
# 查看配额变更日志
grep "quota_abc123" /var/log/quota-service/audit.log | tail -100
```

3. 临时增加配额
```sql
UPDATE quotas
SET max_limit = max_limit + 10  -- 临时增加
WHERE quota_id = 'quota_abc123';
```

4. 清除缓存
```bash
redis-cli DEL "tenant:tenant_abc123:quota:*"
```

#### 配额重置失败

**现象**: 定时重置任务失败

**处理步骤**:
1. 查看监控服务日志
```bash
kubectl logs -f deployment/quota-monitor --tail=200
```

2. 手动执行重置
```bash
curl -X POST http://quota-monitor:8081/reset
```

3. 检查数据库连接
```sql
SHOW PROCESSLIST;
SELECT * FROM information_schema.innodb_trx;
```

## 7. 性能优化

### 7.1 数据库优化

#### 索引优化

```sql
-- 复合索引
CREATE INDEX idx_tenant_resource_reset
ON quotas(tenant_id, resource_type, reset_cycle, last_reset_at);

-- 覆盖索引
CREATE INDEX idx_quota_check_cover
ON quotas(tenant_id, resource_type, max_limit, used_count);
```

#### 分区表

```sql
-- 按租户ID哈希分区
ALTER TABLE quotas
PARTITION BY HASH(tenant_id)
PARTITIONS 16;
```

#### 读写分离

```
主库: 处理写操作
从库: 处理读操作（配额检查）
```

### 7.2 缓存优化

#### 多级缓存

```
L1: 本地缓存（Caffeine） - 1分钟
L2: Redis缓存 - 5分钟
L3: MySQL数据库
```

#### 缓存预热

```bash
# 应用启动时预热缓存
curl -X POST http://quota-service:8080/cache/warmup \
  -d '{"tenant_ids": ["tenant_abc123", "tenant_def456"]}'
```

### 7.3 并发优化

#### 连接池配置

## 8. 备份和恢复

### 8.1 数据备份

#### 每日自动备份

```bash
#!/bin/bash
# backup_quotas.sh

DATE=$(date +%Y%m%d)
BACKUP_DIR=/backup/quotas

# 备份配额表
mysqldump -u root -p${MYSQL_PASSWORD} \
  zker quotas \
  > ${BACKUP_DIR}/quotas_${DATE}.sql

# 压缩备份
gzip ${BACKUP_DIR}/quotas_${DATE}.sql

# 上传到OSS
aws s3 cp ${BACKUP_DIR}/quotas_${DATE}.sql.gz \
  s3://backups/quotas/

# 保留最近30天
find ${BACKUP_DIR} -name "quotas_*.sql.gz" -mtime +30 -delete
```

### 8.2 数据恢复

#### 恢复配额数据

```bash
# 1. 停止应用
kubectl scale deployment/quota-service --replicas=0

# 2. 恢复数据
gunzip < /backup/quotas/quotas_20240101.sql.gz | \
  mysql -u root -p${MYSQL_PASSWORD} zker

# 3. 清除缓存
redis-cli FLUSHALL

# 4. 启动应用
kubectl scale deployment/quota-service --replicas=3
```

## 9. 容量规划

### 9.1 配额容量计算

**假设**:
- 租户数: 10,000
- 每租户平均配额数: 5
- 每日配额检查次数: 100万次

**计算**:
```
总配额记录数 = 10,000 * 5 = 50,000条
每日QPS = 1,000,000 / 86,400 ≈ 12 QPS
峰值QPS = 12 * 5 = 60 QPS
```

### 9.2 资源需求

| 资源 | 配置 |
|------|------|
| MySQL | 4核8G，SSD 500G |
| Redis | 2核4G，内存 8G |
| 应用实例 | 3个副本，每实例 2核4G |
