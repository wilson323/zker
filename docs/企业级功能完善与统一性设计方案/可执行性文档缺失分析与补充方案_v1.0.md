```markdown
# ZKER 核心算法实现指南

## 1. 智能路由引擎算法

### 1.1 意图识别算法 (Intent Recognition)

**算法名称**: HybridIntentMatcher
**输入**:
- user_input: string (用户输入)
- context: RoutingContext (路由上下文)
- historical_conversations: []Conversation (历史会话)

**输出**:
- top_intents: []IntentPrediction (Top-3 意图及置信度)
- confidence_score: float64 (最高置信度)
- matched_entities: []Entity (识别的实体)

**算法步骤**:

```text
算法 HybridIntentMatcher:
输入: user_input, context, historical_conversations
输出: top_intents, confidence_score, matched_entities

1. 预处理 (Preprocessing)
   1.1 文本清洗
       - 去除特殊字符
       - 转小写
       - 去除停用词
   1.2 分词 (Tokenization)
       - 使用 jieba 分词 (中文)
       - 使用 NLTK (英文)

2. 特征提取 (Feature Extraction)
   2.1 TF-IDF 特征
       - 计算 user_input 的 TF-IDF 向量
   2.2 词嵌入特征 (可选)
       - 调用 text-embedding-ada-002
       - 获取 1536 维向量

3. 意图匹配 (Intent Matching)
   3.1 基于规则的匹配
       FOR EACH intent_rule IN intent_rules:
           IF user_input MATCHES intent_rule.pattern:
               ADD (intent_rule.intent, 1.0) TO candidates

   3.2 基于相似度的匹配
       FOR EACH intent_sample IN intent_samples:
           similarity = COSINE_SIMILARITY(
               user_input_embedding,
               intent_sample.embedding
           )
           IF similarity > 0.7:
               ADD (intent_sample.intent, similarity) TO candidates

   3.3 基于模型的匹配 (可选)
       IF use_model_matching:
           result = intent_model.predict(user_input)
           ADD (result.intent, result.confidence) TO candidates

4. 结果聚合 (Aggregation)
   4.1 去重
   4.2 置信度加权
       final_confidence = 0.3 * rule_confidence
                       + 0.4 * similarity_confidence
                       + 0.3 * model_confidence
   4.3 排序
   4.4 取 Top-3

5. 实体提取 (Entity Extraction)
   5.1 正则表达式提取
   5.2 NER 模型提取 (可选)

6. 返回结果
   RETURN top_3_intents, max_confidence, entities
```

**复杂度分析**:
- 时间复杂度: O(n * m) (n: 意图样本数, m: 特征维度)
- 空间复杂度: O(m)
- 性能优化: 使用 Faiss 加速向量检索

**参数调优**:
- 相似度阈值: 0.7 (可调整)
- 权重分配: [0.3, 0.4, 0.3] (可调整)
- Top-K: 3 (可调整)

**异常处理**:
- user_input 为空: 返回默认意图
- 意图样本为空: 返回默认意图
- 模型调用失败: 降级到规则匹配

### 1.2 路由决策算法 (Routing Decision)

**算法名称**: ScoreBasedRouter
**输入**:
- intents: []IntentPrediction (Top-3 意图)
- context: RoutingContext (路由上下文)
- service_candidates: []Service (候选服务)

**输出**:
- selected_service: Service (选中的服务)
- routing_decision_id: string (决策 ID)
- decision_reason: string (决策原因)

**算法步骤**:

```text
算法 ScoreBasedRouter:
输入: intents, context, service_candidates
输出: selected_service, decision_id, decision_reason

1. 候选服务生成 (Candidate Generation)
   1.1 根据意图匹配服务
       candidates = []
       FOR EACH intent IN intents:
           matched_services = services_by_intent[intent.name]
           candidates.ADD_ALL(matched_services)

   1.2 过滤不可用服务
       available_candidates = candidates.FILTER(
           service.status == 'available'
           AND service.health_score > 0.5
       )

   1.3 权限过滤
       authorized_candidates = available_candidates.FILTER(
           user_has_permission(context.user_id, service)
       )

2. 服务评分 (Service Scoring)
   FOR EACH service IN authorized_candidates:
       score = 0

       // 2.1 意图匹配度 (权重 0.3)
       intent_match_score = intents[0].confidence
       score += 0.3 * intent_match_score

       // 2.2 服务负载 (权重 0.2)
       load_score = 1.0 - (service.current_load / service.max_load)
       score += 0.2 * load_score

       // 2.3 历史成功率 (权重 0.2)
       success_score = service.success_rate
       score += 0.2 * success_score

       // 2.4 地域亲和性 (权重 0.1)
       IF service.region == context.user_region:
           score += 0.1

       // 2.5 成本考虑 (权重 0.1)
       cost_score = 1.0 - normalize_cost(service.cost)
       score += 0.1 * cost_score

       // 2.6 A/B 测试分流 (权重 0.1)
       IF ab_test_enabled:
           score += 0.1 * ab_test_weight(service, context.user_id)

       service.final_score = score

3. 选择最优服务
   sorted_services = authorized_candidates.SORT_BY('final_score', DESC)
   selected_service = sorted_services[0]

4. 记录决策日志
   log_routing_decision({
       decision_id: generate_uuid(),
       user_id: context.user_id,
       tenant_id: context.tenant_id,
       intents: intents,
       candidates: authorized_candidates,
       selected_service: selected_service,
       decision_reason: explain_routing(selected_service)
   })

5. A/B 测试记录 (if enabled)
   IF ab_test_enabled:
       record_ab_test_event(context.user_id, selected_service)

6. 返回结果
   RETURN selected_service, decision_id, decision_reason
```

**复杂度分析**:
- 时间复杂度: O(n log n) (n: 候选服务数)
- 空间复杂度: O(n)

**优化策略**:
- 使用缓存减少重复计算
- 预筛选候选服务减少排序开销

## 2. RBAC 权限判断算法

### 2.1 数据权限判断算法

**算法名称**: RowLevelPermissionChecker
**输入**:
- user_id: string
- resource_type: string
- resource_id: string
- action: string (READ, WRITE, DELETE)

**输出**:
- allowed: boolean
- reason: string

**算法步骤**:

```text
算法 RowLevelPermissionChecker:
输入: user_id, resource_type, resource_id, action
输出: allowed, reason

1. 获取用户角色
   user_roles = get_user_roles(user_id)

2. 获取资源权限规则
   permission_rules = get_data_permissions(
       resource_type,
       user_roles
   )

3. 检查权限级别
   FOR EACH rule IN permission_rules:
       CASE rule.scope:
           'ALL':
               // 所有数据
               RETURN true, 'Has permission to all data'

           'OWN':
               // 仅自己的数据
               resource = get_resource(resource_type, resource_id)
               IF resource.created_by == user_id:
                   RETURN true, 'Has permission to own data'
               ELSE:
                   RETURN false, 'No permission to others data'

           'DEPARTMENT':
               // 本部门数据
               resource = get_resource(resource_type, resource_id)
               user_dept = get_user_department(user_id)
               IF resource.department_id == user_dept.id:
                   RETURN true, 'Has permission to department data'
               ELSE:
                   RETURN false, 'No permission to other department data'

           'ORGANIZATION':
               // 本组织数据
               resource = get_resource(resource_type, resource_id)
               user_org = get_user_organization(user_id)
               IF resource.organization_id == user_org.id:
                   RETURN true, 'Has permission to organization data'
               ELSE:
                   RETURN false, 'No permission to other organization data'

           'CUSTOM':
               // 自定义规则
               IF evaluate_custom_rule(rule, user_id, resource_id):
                   RETURN true, 'Custom permission rule passed'
               ELSE:
                   RETURN false, 'Custom permission rule failed'

   RETURN false, 'No matching permission rule'
```

**权限优先级**:

## 4. 工作流执行引擎算法

### 4.1 DAG 执行算法

**算法名称**: WorkflowDAGExecutor
**输入**:
- workflow: Workflow (工作流定义)
- input_data: Map (输入数据)
- context: ExecutionContext (执行上下文)

**输出**:
- execution_result: ExecutionResult (执行结果)
- execution_id: string (执行 ID)

**算法步骤**:

```text
算法 WorkflowDAGExecutor:
输入: workflow, input_data, context
输出: execution_result, execution_id

1. 初始化
   execution_id = generate_uuid()
   execution_result = {
       id: execution_id,
       workflow_id: workflow.id,
       status: 'running',
       start_time: now()
   }

2. 构建 DAG
   dag = build_dag(workflow.nodes, workflow.edges)

3. 拓扑排序
   try:
       sorted_nodes = topological_sort(dag)
   except CycleDetected:
       RETURN error, 'Workflow contains cycle'

4. 执行节点
   completed_nodes = []
   failed_nodes = []
   node_results = {}

   FOR EACH node IN sorted_nodes:
       // 4.1 检查前置节点是否完成
       IF NOT all_dependencies_completed(node, completed_nodes):
           CONTINUE

       // 4.2 准备节点输入
       node_input = prepare_node_input(
           node,
           input_data,
           node_results
       )

       // 4.3 执行节点
       try:
           node_result = execute_node(node, node_input, context)
           node_results[node.id] = node_result
           completed_nodes.ADD(node)

           // 4.4 记录执行日志
           log_node_execution(execution_id, node, node_result)

       except Exception as e:
           failed_nodes.ADD(node)
           log_node_error(execution_id, node, e)

           // 4.5 错误处理策略
           IF node.error_strategy == 'stop':
               execution_result.status = 'failed'
               execution_result.error = e
               RETURN execution_result, execution_id
           ELSE IF node.error_strategy == 'continue':
               CONTINUE
           ELSE IF node.error_strategy == 'retry':
               retry_count = 0
               WHILE retry_count < node.max_retries:
                   try:
                       node_result = execute_node(node, node_input, context)
                       node_results[node.id] = node_result
                       completed_nodes.ADD(node)
                       BREAK
                   except Exception:
                       retry_count += 1
               IF retry_count == node.max_retries:
                   execution_result.status = 'failed'
                   RETURN execution_result, execution_id

5. 收集输出
   output_data = collect_workflow_output(
       workflow.output_nodes,
       node_results
   )

6. 更新执行状态
   execution_result.status = 'completed'
   execution_result.output = output_data
   execution_result.end_time = now()
   execution_result.duration = end_time - start_time

7. 返回结果
   RETURN execution_result, execution_id
```

**复杂度分析**:
- 时间复杂度: O(V + E) (V: 节点数, E: 边数)
- 空间复杂度: O(V)

**并发优化**:
- 并行执行无依赖的节点
- 使用线程池/协程池限制并发度

## 5. 知识库检索算法

### 5.1 混合检索算法

**算法名称**: HybridKnowledgeRetriever
**输入**:
- query: string (查询问题)
- knowledge_base_id: string (知识库 ID)
- top_k: integer (返回结果数)

**输出**:
- retrieved_documents: []Document (检索到的文档)
- scores: []float64 (相关度分数)

**算法步骤**:

```text
算法 HybridKnowledgeRetriever:
输入: query, knowledge_base_id, top_k
输出: retrieved_documents, scores

1. 查询预处理
   cleaned_query = preprocess_text(query)
   query_embedding = get_embedding(cleaned_query)

2. 向量检索 (Semantic Search)
   // 2.1 Milvus 向量检索
   vector_results = milvus_search({
       collection: knowledge_base_id,
       vector: query_embedding,
       top_k: top_k * 2  // 召回更多，后续重排序
   })

   // 2.2 计算向量相似度分数
   FOR EACH doc IN vector_results:
       doc.vector_score = cosine_similarity(
           query_embedding,
           doc.embedding
       )

3. 关键词检索 (Keyword Search)
   // 3.1 Elasticsearch 全文检索
   keyword_results = elasticsearch_search({
       index: knowledge_base_id,
       query: cleaned_query,
       top_k: top_k * 2
   })

   // 3.2 计算 BM25 分数
   FOR EACH doc IN keyword_results:
       doc.keyword_score = doc._score

4. 结果融合 (Result Fusion)
   // 4.1 合并结果
   all_results = merge(vector_results, keyword_results)

   // 4.2 去重
   unique_results = deduplicate(all_results)

   // 4.3 重排序 (Reciprocal Rank Fusion, RRF)
   FOR EACH doc IN unique_results:
       doc.final_score = 0.6 * doc.vector_score
                      + 0.4 * doc.keyword_score

   // 4.4 排序
   sorted_results = unique_results.SORT_BY('final_score', DESC)

   // 4.5 取 Top-K
   top_results = sorted_results[0:top_k]

5. 返回结果
   RETURN top_results, top_results.final_score
```

**参数调优**:
- 向量检索权重: 0.6 (可调整)
- 关键词检索权重: 0.4 (可调整)
- Top-K: 5-10 (可调整)

## 6. 订阅配额检查算法

### 6.1 多维配额检查算法

**算法名称**: MultiDimensionalQuotaChecker
**输入**:
- tenant_id: string (租户 ID)
- resource_type: string (资源类型)
- action: string (CREATE, READ, UPDATE, DELETE)
- quantity: integer (数量)

**输出**:
- allowed: boolean
- reason: string
- remaining_quota: integer

**算法步骤**:

```text
算法 MultiDimensionalQuotaChecker:
输入: tenant_id, resource_type, action, quantity
输出: allowed, reason, remaining_quota

1. 获取租户订阅
   subscription = get_active_subscription(tenant_id)
   IF NOT subscription:
       RETURN false, 'No active subscription', 0

2. 获取订阅方案配额
   plan = get_subscription_plan(subscription.plan_id)
   quotas = plan.quotas[resource_type]

3. 获取当前使用量
   usage = get_tenant_usage(tenant_id, resource_type)

4. 检查维度配额
   FOR EACH dimension IN quotas.dimensions:

       // 4.1 时间维度配额
       IF dimension.type == 'time':
           IF dimension.period == 'hourly':
               current_usage = usage.last_hour_count
           ELSE IF dimension.period == 'daily':
               current_usage = usage.last_day_count
           ELSE IF dimension.period == 'monthly':
               current_usage = usage.last_month_count

           IF current_usage + quantity > dimension.limit:
               RETURN false,
                   f'Exceeds {dimension.period} quota: {current_usage + quantity}/{dimension.limit}',
                   dimension.limit - current_usage

       // 4.2 总量维度配额
       ELSE IF dimension.type == 'total':
           current_usage = usage.total_count
           IF current_usage + quantity > dimension.limit:
               RETURN false,
                   f'Exceeds total quota: {current_usage + quantity}/{dimension.limit}',
                   dimension.limit - current_usage

       // 4.3 并发维度配额
       ELSE IF dimension.type == 'concurrent':
           current_usage = usage.concurrent_count
           IF current_usage + quantity > dimension.limit:
               RETURN false,
                   f'Exceeds concurrent quota: {current_usage + quantity}/{dimension.limit}',
                   dimension.limit - current_usage

5. 检查配额升级
   IF plan.allow_quota_exceed AND usage.can_upgrade:
       // 允许超额，但需要付费
       extra_cost = calculate_extra_cost(quantity, plan)
       RETURN true,
           f'Quota exceeded, extra cost: {extra_cost}',
       0

6. 配额检查通过
   RETURN true, 'Quota check passed', remaining_quota

7. 记录配额使用
   record_quota_usage(tenant_id, resource_type, quantity)
```

- 并发维度: 并发数限制

## 7. 数据脱敏算法

### 7.1 敏感数据脱敏算法

**算法名称**: SensitiveDataMasker
**输入**:
- data: string (原始数据)
- data_type: string (数据类型)
- user_role: string (用户角色)

**输出**:
- masked_data: string (脱敏后的数据)

**算法步骤**:

```text
算法 SensitiveDataMasker:
输入: data, data_type, user_role
输出: masked_data

1. 检查是否需要脱敏
   IF user_role IN ['admin', 'system_admin']:
       RETURN data  // 管理员不脱敏

   IF NOT is_sensitive_data(data_type):
       RETURN data  // 非敏感数据不脱敏

2. 根据数据类型脱敏
   CASE data_type:
       'phone':
           // 手机号: 138****1234
           masked_data = data[0:3] + '****' + data[7:11]

       'email':
           // 邮箱: u***@example.com
           parts = data.split('@')
           username = parts[0]
           domain = parts[1]
           masked_username = username[0] + '***'
           masked_data = masked_username + '@' + domain

       'id_card':
           // 身份证: 110101********1234
           masked_data = data[0:6] + '********' + data[14:18]

       'bank_card':
           // 银行卡: 6222********1234
           masked_data = data[0:4] + '****' + '*' * 4 + data[12:16]

       'name':
           // 姓名: 王**
           masked_data = data[0] + '**'

       'address':
           // 地址: 北京市朝阳区****
           masked_data = data[0:6] + '****'

       DEFAULT:
           masked_data = data

3. 返回脱敏数据
   RETURN masked_data
```

**脱敏规则**:
- 管理员: 不脱敏
- 数据所有者: 不脱敏
- 普通用户: 完全脱敏
- 审计人员: 部分脱敏
```

- 服务不可用: 恢复服务

### 4. 知识库检索结果不准确
**症状**:
- 检索结果与问题不相关
- 相关文档排到后面

**排查步骤**:
1. 检查查询向量
   ```python
   # 查看查询向量
   query_embedding = get_embedding("用户问题")
   print(query_embedding[:10])  # 打印前 10 维
   ```

2. 检查文档向量
   ```sql
   SELECT document_id, chunk_text, similarity_score
   FROM knowledge_chunks
   WHERE knowledge_base_id = 'xxx'
   ORDER BY similarity_score DESC
   LIMIT 10;
   ```

3. 检查检索参数
   - top_k 是否合理 (建议 5-10)
   - score_threshold 是否合理 (建议 0.7)

**解决方案**:
- 向量质量差: 重新向量化
- 检索参数不合理: 调整参数
- 文档分块不合理: 重新分块

### 5. 数据库连接池耗尽
**症状**:
- 返回错误码: DB504
- 大量请求超时

**排查步骤**:
1. 检查连接池状态
   ```sql
   SHOW STATUS LIKE 'Threads_connected';
   SHOW STATUS LIKE 'Max_used_connections';
   ```

2. 检查慢查询
   ```sql
   SELECT * FROM mysql.slow_log
   ORDER BY query_time DESC
   LIMIT 10;
   ```

3. 检查连接泄漏
   ```bash
   # 查看长时间运行的连接
   mysql -e "SHOW PROCESSLIST;" | grep "Time"
   ```

**解决方案**:
- 增加连接池大小
- 优化慢查询
- 修复连接泄漏 (确保 Close/Release)
