## 1. 引言

### 1.1 编写目的

本文档旨在详细描述 zker 平台的所有软件需求，包括功能需求、非功能需求、接口需求、质量属性和约束条件。本文档面向：
- 产品经理：确认产品功能范围和验收标准
- 系统架构师：理解系统架构设计要求
- 软件开发人员：明确开发目标和实现细节
- 测试人员：制定测试计划和验收标准
- 项目干系人：了解项目整体需求

### 1.2 项目背景

zker 是一个开源的一站式 AI Agent 开发平台，旨在为开发者和企业提供低代码/无代码的 AI 应用开发能力。项目源于服务于数万企业和数百万开发者的商业版 Coze 开发平台，现已将其核心引擎完全开源。

**项目目标：**
- 降低 AI Agent 开发门槛，让更多开发者能够快速构建智能应用
- 提供完整的开发工具链，从设计、调试到部署
- 支持多种 AI 模型和服务集成
- 构建开放的开发者生态系统

**项目范围：**
- ✅ **包含：**
  - AI Agent 构建与管理系统
  - 可视化工作流编辑器
  - 知识库管理
  - 插件系统
  - 对话管理
  - 开放 API 和 SDK
  - 多用户协作空间

- ❌ **不包含：**
  - AI 模型训练和微调服务
  - 商业化计费和订阅管理
  - 企业级 SSO 和权限系统（开源版）
  - 多租户隔离（商业版专属）

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| **AI Agent** | 具备自主决策能力的智能代理，能够使用工具、记忆和知识完成复杂任务 |
| **Workflow** | 工作流，通过可视化方式编排业务逻辑的执行流程 |
| **Knowledge Base** | 知识库，存储和管理用于 RAG（检索增强生成）的文档数据 |
| **Plugin** | 插件，扩展 Agent 能力的外部工具集成 |
| **Prompt** | 提示词，用于指导 AI 模型生成响应的文本指令 |
| **Memory** | 记忆，Agent 存储和使用的历史对话信息 |
| **RAG** | Retrieval-Augmented Generation，检索增强生成 |
| **LLM** | Large Language Model，大语言模型 |

## 2. 总体描述

### 2.1 产品概述

zker 是一个基于微服务架构的一站式 AI Agent 开发平台，采用前后端分离设计：

**前端技术栈：**
- React 18 + TypeScript
- Semi Design UI 框架
- Tailwind CSS
- Rsbuild（基于 Rspack）构建系统
- Rush.js Monorepo 管理 135+ 个包

**后端技术栈：**
- Go 1.23.4+
- Hertz HTTP 框架
- 领域驱动设计（DDD）架构
- 微服务架构

**基础设施：**
- MySQL 8.4.5（主数据库）
- Redis 8.0（缓存）
- Elasticsearch 8.18.0（搜索引擎）
- Milvus v2.5.10（向量数据库）
- MinIO（对象存储）
- etcd 3.5（配置中心）
- NSQ（消息队列）

### 2.2 系统架构

系统采用四层架构模式：

```
┌─────────────────────────────────────────────────────┐
│                   前端展示层                          │
│         (React + TypeScript + Semi UI)              │
│   - Agent IDE  - Workflow Editor  - Chat Area       │
└─────────────────────────────────────────────────────┘
                         ↕ HTTP/WebSocket
┌─────────────────────────────────────────────────────┐
│                   API 网关层                          │
│              (Hertz + Middleware)                    │
│   - 认证授权  - 限流熔断  - 日志监控                  │
└─────────────────────────────────────────────────────┘
                         ↕
┌─────────────────────────────────────────────────────┐
│                  应用服务层                           │
│              (DDD - Application)                     │
│  - Agent Service  - Workflow Service  - Chat Service │
└─────────────────────────────────────────────────────┘
                         ↕
┌─────────────────────────────────────────────────────┐
│                  领域层 (Domain)                     │
│   - Agent  - Workflow  - Conversation  - Knowledge   │
└─────────────────────────────────────────────────────┘
                         ↕
┌─────────────────────────────────────────────────────┐
│                 基础设施层 (Infra)                    │
│  - MySQL  - Redis  - ES  - Milvus  - MinIO  - NSQ   │
└─────────────────────────────────────────────────────┘
```

## 3. 功能需求

### 3.1 用户与空间管理 (FR-USR)

#### FR-USR-001 用户注册与登录

**需求描述：**
用户可以通过邮箱/手机号注册账号，使用用户名密码登录系统。

**用例：**
- **主要角色：** 未注册用户、已注册用户
- **前置条件：**
  - 系统服务正常运行
  - MySQL 数据库连接正常
- **操作步骤：**
  1. 用户访问注册页面 `/sign`
  2. 输入用户名、邮箱、密码
  3. 点击"注册"按钮
  4. 系统验证输入合法性
  5. 创建用户记录，生成用户 ID
  6. 自动登录并跳转到首页
- **后置条件：**
  - 用户信息持久化到数据库
  - 创建默认个人空间
  - 生成会话 Token

**验收标准：**
- ✅ 用户名长度 3-20 个字符，仅支持字母、数字、下划线
- ✅ 密码至少 8 位，包含大小写字母和数字
- ✅ 邮箱格式验证正确
- ✅ 重复用户名/邮箱拒绝注册
- ✅ 密码使用 bcrypt 加密存储
- ✅ 登录失败 5 次锁定账号 30 分钟

#### FR-USR-002 工作空间管理

**需求描述：**
用户可以创建个人空间或加入团队空间，支持成员邀请和权限管理。

**用户故事：**
> 作为团队负责人，我希望能够创建团队空间并邀请成员加入，以便团队协作开发 AI 应用。

**功能点：**
- 创建空间（个人/团队）
- 编辑空间信息（名称、描述、头像）
- 邀请成员加入（通过邮箱/链接）
- 设置成员角色（所有者/管理员/成员/访客）
- 移除空间成员
- 切换当前空间
- 删除空间（仅所有者）

**验收标准：**
- ✅ 每个用户最多创建 10 个个人空间
- ✅ 团队空间最多支持 100 个成员
- ✅ 成员角色权限隔离正确
- ✅ 删除空间时清空所有关联资源

### 3.2 Agent 构建器 (FR-AGENT)

#### FR-AGENT-001 Agent 创建与配置

**需求描述：**
用户可以创建 AI Agent 并配置其基本信息、能力、触发器等。

**功能清单：**

| 配置项 | 说明 | 是否必填 |
|--------|------|----------|
| Agent 名称 | 唯一标识，3-50 字符 | 必填 |
| Agent 描述 | 功能说明，500 字符以内 | 可选 |
| 头像图片 | 支持上传或选择默认头像 | 可选 |
| 系统提示词 | 定义 Agent 角色和行为 | 必填 |
| 开场白 | 首次对话时的欢迎语 | 可选 |
| 模型配置 | 选择 LLM 和参数 | 必填 |
| 知识库 | 关联知识库资源 | 可选 |
| 插件工具 | 启用官方/自定义插件 | 可选 |
| 数据库 | 关联数据库资源 | 可选 |
| 工作流 | 关联工作流资源 | 可选 |
| 变量 | 配置环境变量 | 可选 |
| 记忆设置 | 开启/关闭对话记忆 | 可选 |
| 隐私设置 | 是否允许公开搜索 | 可选 |

**验收标准：**
- ✅ Agent 名称在空间内唯一
- ✅ 系统提示词支持变量引用
- ✅ 模型配置实时生效
- ✅ 关联资源引用验证正确性

#### FR-AGENT-002 Agent 发布与分享

**需求描述：**
用户可以将 Agent 发布到不同渠道，支持公开分享和私有访问。

**发布渠道：**
- 公开链接：生成唯一 URL，任何人可访问
- 私有链接：需要登录且在空间内才能访问
- 嵌入代码：生成 iframe/SDK 集成代码
- API 集成：提供 OpenAPI 接口

**版本管理：**
- 支持多版本发布（v1.0, v1.1...）
- 版本回滚能力
- 发布日志记录
- 灰度发布（可选）

**验收标准：**
- ✅ 公开链接不可预测（UUID）
- ✅ 私有链接权限校验正确
- ✅ 版本回滚秒级完成
- ✅ 嵌入代码适配移动端

### 3.3 工作流引擎 (FR-WORKFLOW)

#### FR-WORKFLOW-001 可视化编辑器

**需求描述：**
提供基于画布的工作流可视化编辑器，支持拖拽节点和连线。

**核心功能：**
- 节点库：开始、结束、变量、条件判断、循环、API 调用、代码执行、LLM 调用、插件、数据库操作等
- 画布操作：拖拽节点、连线、缩放、对齐、网格吸附
- 节点配置：参数设置、变量映射、错误处理
- 连线规则：数据流向控制、分支合并
- 快捷键：复制/粘贴/删除/撤销/重做
- 辅助功能：搜索节点、格式化、检查错误

**验收标准：**
- ✅ 支持 50+ 种节点类型
- ✅ 画布流畅度 ≥ 60 FPS
- ✅ 支持节点嵌套（子工作流）
- ✅ 自动保存（30 秒间隔）
- ✅ 最大支持 500 个节点的工作流

#### FR-WORKFLOW-002 工作流执行引擎

**需求描述：**
后端提供工作流执行引擎，支持同步/异步执行、超时控制、错误重试。

**执行模式：**
- 同步执行：等待完成后返回结果
- 异步执行：返回执行 ID，后台执行
- 调试模式：逐步执行，显示中间状态

**特性：**
- DAG 调度（有向无环图）
- 并行执行（无依赖节点）
- 超时控制（节点级/流程级）
- 错误处理（重试/跳过/终止）
- 状态持久化
- 执行日志记录

**验收标准：**
- ✅ 单次执行超时 ≤ 5 分钟（可配置）
- ✅ 支持最多 10 层嵌套调用
- ✅ 失败节点自动重试 3 次
- ✅ 执行日志保留 30 天
- ✅ 并发执行能力 ≥ 100 QPS

### 3.4 知识库管理 (FR-KNOWLEDGE)

#### FR-KNOWLEDGE-001 文档上传与处理

**需求描述：**
用户可以上传多种格式的文档到知识库，系统自动进行切片和向量化。

**支持格式：**
- 文本：TXT、Markdown、PDF、Word、Excel
- 网页：URL 爬取
- 结构化数据：JSON、CSV

**处理流程：**
1. 文件上传到 MinIO
2. 提取文本内容（解析器）
3. 文本分块（Chunking）
   - 固定大小：500-1000 tokens
   - 语义分块：按段落/章节
4. 向量化（Embedding）
   - 调用 Embedding 模型
   - 存储到 Milvus
5. 建立索引（Elasticsearch）

**验收标准：**
- ✅ 单文件大小限制 100MB
- ✅ 支持批量上传（最多 50 个文件）
- ✅ 分块后余弦相似度 ≥ 0.85
- ✅ 向量化延迟 ≤ 5 秒/MB
- ✅ 支持增量更新

#### FR-KNOWLEDGE-002 检索与引用

**需求描述：**
Agent 在对话时可以自动检索知识库内容并引用。

**检索策略：**
- 向量检索：Milvus 相似度搜索（Top-K）
- 混合检索：向量 + 全文检索（ES）
- 重排序（Rerank）：根据相关性重新排序

**引用格式：**
```
[来源: 文档名称, 页码/章节]
```

**验收标准：**
- ✅ 检索延迟 ≤ 500ms
- ✅ Top-5 准确率 ≥ 90%
- ✅ 支持跨知识库检索
- ✅ 引用来源可追溯

### 3.5 插件系统 (FR-PLUGIN)

#### FR-PLUGIN-001 官方插件

**需求描述：**
系统提供预置的官方插件，覆盖常见第三方服务集成。

**插件列表（部分）：**
- 搜索引擎：Google Search、Bing Search

- 生产力：Google Calendar、Notion、Trello
- 开发工具：GitHub、GitLab、Jira
- 数据分析：Wolfram Alpha、Calculator
- 其他：Weather、Time、Translator

**认证方式：**
- API Key：用户手动配置
- OAuth 2.0：标准授权流程

**验收标准：**
- ✅ 官方插件数量 ≥ 20 个
- ✅ OAuth 授权流程符合 RFC 6749
- ✅ API Key 加密存储
- ✅ 插件调用失败率 ≤ 1%

#### FR-PLUGIN-002 自定义插件

**需求描述：**
高级用户可以创建自定义插件，扩展 Agent 能力。

**插件类型：**
- API 插件：HTTP/HTTPS 接口
- WebSocket 插件：长连接通信
- 本地插件：代码执行（沙箱环境）

**开发流程：**
1. 定义插件清单（manifest.json）
2. 配置 API 端点和参数
3. 编写请求/响应映射逻辑
4. 测试插件功能
5. 发布到空间或公开市场

**安全机制：**
- 输入验证和过滤
- 输出脱敏
- 调用频率限制
- 权限控制

**验收标准：**
- ✅ 插件清单符合 JSON Schema
- ✅ 支持 GET/POST/PUT/DELETE 方法
- ✅ 支持自定义 Header 和 Body
- ✅ 沙箱环境隔离执行

### 3.6 对话管理 (FR-CONVERSATION)

#### FR-CONVERSATION-001 多轮对话

**需求描述：**
支持用户与 Agent 进行多轮对话，维护上下文和状态。

**对话模式：**
- 单轮对话：无记忆，每次独立
- 多轮对话：保留历史上下文
- 会话重置：清空上下文重新开始

**消息类型：**
- 文本消息
- 图片消息（上传/生成）
- 文件消息
- 富文本消息（Markdown）
- 工作流调用结果

**流式响应：**
- Server-Sent Events (SSE)
- 逐字输出（打字机效果）
- 中断能力（用户可打断）

**验收标准：**
- ✅ 首字响应时间 ≤ 1 秒
- ✅ 支持并发对话数 ≥ 1000
- ✅ 上下文窗口最大 10K tokens
- ✅ 消息持久化延迟 ≤ 100ms

#### FR-CONVERSATION-002 调试面板

**需求描述：**

#### API 接口规范

**基础 URL：**
```
生产环境：https://api.coze.com
开发环境：http://localhost:8888
```

**认证方式：**
```
Authorization: Bearer {personal_access_token}
```

**请求格式：**
```json
Content-Type: application/json
Accept: application/json
```

**响应格式：**
```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req_123456"
}
```

**错误响应：**
```json
{
  "code": 40001,
  "message": "Invalid parameter",
  "data": null,
  "requestId": "req_123456"
}
```

#### 核心 API 列表

**Agent 管理：**
- `POST /api/bots` - 创建 Agent
- `GET /api/bots` - 列出 Agent
- `GET /api/bots/{botId}` - 获取 Agent 详情
- `PUT /api/bots/{botId}` - 更新 Agent
- `DELETE /api/bots/{botId}` - 删除 Agent
- `POST /api/bots/{botId}/publish` - 发布 Agent

**对话接口：**
- `POST /api/chat` - 发送消息（流式）
- `GET /api/conversations/{conversationId}` - 获取对话历史
- `DELETE /api/conversations/{conversationId}` - 删除对话

**工作流接口：**
- `POST /api/workflows` - 创建工作流
- `POST /api/workflows/{workflowId}/execute` - 执行工作流
- `GET /api/workflows/{workflowId}/runs` - 获取执行记录

**知识库接口：**
- `POST /api/knowledge` - 创建知识库
- `POST /api/knowledge/{kbId}/documents` - 上传文档
- `POST /api/knowledge/{kbId}/search` - 检索文档

**完整 API 文档：** 参见 `docs/api/` 目录
