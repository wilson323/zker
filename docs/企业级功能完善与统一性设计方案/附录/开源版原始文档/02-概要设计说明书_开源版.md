## 1. 系统概述

### 1.1 设计目标

zker 概要设计旨在定义系统的整体架构、模块划分、接口关系和技术选型，为详细设计和开发实现提供指导。

**核心设计原则：**
- **高内聚低耦合：** 模块职责单一，通过接口通信
- **可扩展性：** 支持水平扩展和模块化扩展
- **高可用性：** 无状态设计，支持故障转移
- **安全性：** 多层防护，数据加密
- **性能优先：** 缓存策略，异步处理

### 1.2 系统范围

**包含内容：**
- ✅ 前端应用（React SPA）
- ✅ 后端 API（Go 微服务）
- ✅ 数据库设计（MySQL/Redis）
- ✅ 基础设施（Docker Compose）
- ✅ 接口规范（RESTful API）

**不包含内容：**
- ❌ AI 模型训练服务
- ❌ 第三方计费系统
- ❌ 企业级单点登录（SSO）

#### 2.2.3 应用层 (Application Layer)

**职责：** 编排业务逻辑，协调领域对象完成用例

**组织结构：**
```
backend/application/
├── agent/           # Agent 应用服务
├── conversation/    # 对话应用服务
├── workflow/        # 工作流应用服务
├── knowledge/       # 知识库应用服务
├── plugin/          # 插件应用服务
├── user/            # 用户应用服务
└── publish/         # 发布应用服务
```

**应用服务示例：**
```go
// application/agent/service.go
type AgentService struct {
    agentRepo    domain.AgentRepository
    knowledgeSvc *KnowledgeService
    pluginSvc    *PluginService
    eventBus     event.Bus
}

func (s *AgentService) CreateAgent(ctx context.Context, req *CreateAgentReq) (*Agent, error) {
    // 1. 参数验证
    if err := s.validateCreateAgentReq(req); err != nil {
        return nil, err
    }

    // 2. 创建领域对象
    agent := domain.NewAgent(req)

    // 3. 业务规则验证
    if err := s.agentRepo.ValidateAgentName(ctx, agent); err != nil {
        return nil, err
    }

    // 4. 持久化
    if err := s.agentRepo.Save(ctx, agent); err != nil {
        return nil, err
    }

    // 5. 发布领域事件
    s.eventBus.Publish(ctx, &AgentCreatedEvent{Agent: agent})

    return agent, nil
}
```

**领域实体示例：**
```go
// domain/agent/agent.go
type Agent struct {
    id              AgentID
    spaceID         SpaceID
    name            string
    description     string
    avatar          string
    systemPrompt    string
    openingRemark   string
    modelConfig     ModelConfig
    knowledgeBases  []KnowledgeBaseID
    plugins         []PluginID
    workflows       []WorkflowID
    variables       Variables
    memoryConfig    MemoryConfig
    privacyConfig   PrivacyConfig
    status          AgentStatus
    createdAt       time.Time
    updatedAt       time.Time
}

// 业务方法
func (a *Agent) Validate() error {
    if len(a.name) < 3 || len(a.name) > 50 {
        return ErrInvalidAgentName
    }
    if a.systemPrompt == "" {
        return ErrEmptySystemPrompt
    }
    return nil
}

func (a *Agent) AddKnowledgeBase(kbID KnowledgeBaseID) error {
    for _, id := range a.knowledgeBases {
        if id == kbID {
            return ErrKnowledgeBaseAlreadyAdded
        }
    }
    a.knowledgeBases = append(a.knowledgeBases, kbID)
    a.updatedAt = time.Now()
    return nil
}
```

### 2.3 关键架构模式

#### 2.3.1 适配器模式 (Adapter Pattern)

**目的：** 解耦核心业务与外部依赖

**应用场景：**
- UI 适配器：隔离不同 UI 实现
- API 适配器：隔离不同 API 版本
- 存储适配器：支持多种存储后端

**示例：**
```
@zker/bot-plugin-ui-base         # 基础 UI 组件
           ↓
@zker/bot-plugin-ui-adapter      # UI 适配器
           ↓
@coze-agent-ide/bot-plugin              # Agent IDE 插件模块
```

#### 2.3.2 仓储模式 (Repository Pattern)

**目的：** 抽象数据访问逻辑

**接口定义：**
```go
// domain/agent/repository.go
type AgentRepository interface {
    Save(ctx context.Context, agent *Agent) error
    FindByID(ctx context.Context, id AgentID) (*Agent, error)
    FindBySpaceID(ctx context.Context, spaceID SpaceID) ([]*Agent, error)
    Update(ctx context.Context, agent *Agent) error
    Delete(ctx context.Context, id AgentID) error
    ValidateAgentName(ctx context.Context, agent *Agent) error
}
```

**实现：**
```go
// infra/orm/agent_repository.go
type agentRepository struct {
    db *gorm.DB
}

func (r *agentRepository) Save(ctx context.Context, agent *Agent) error {
    po := ConvertToPO(agent)
    return r.db.WithContext(ctx).Create(po).Error
}
```

#### 2.3.3 事件驱动架构 (Event-Driven)

**目的：** 异步解耦，提高系统响应性

**事件流：**
```
领域事件 → 事件总线 → 事件处理器 → 外部系统
```

**示例：**
```go
// 发布事件
eventBus.Publish(ctx, &AgentCreatedEvent{
    AgentID: agent.id,
    SpaceID: agent.spaceID,
    Timestamp: time.Now(),
})

// 订阅事件
eventBus.Subscribe("AgentCreated", func(evt Event) {
    agentCreatedEvt := evt.(*AgentCreatedEvent)
    // 发送通知
    // 更新搜索索引
    // 记录审计日志
})
```

## 4. 数据库设计

### 4.1 数据库选型

**主数据库：MySQL 8.4.5**
- 理由：成熟稳定、ACID 事务、丰富索引支持、社区活跃

**缓存层：Redis 8.0**
- 理由：高性能、丰富数据结构、持久化支持

**搜索引擎：Elasticsearch 8.18.0**
- 理由：全文检索、中文分词（SmartCN）、分布式架构

**向量数据库：Milvus v2.5.10**
- 理由：高性能向量检索、支持 Embedding 索引、云原生架构

**对象存储：MinIO**
- 理由：S3 兼容、高性能、易于部署

### 4.2 数据库分层策略

```
┌─────────────────────────────────────┐
│         应用层 (Application)         │
└─────────────────────────────────────┘
                 ↓
┌─────────────────────────────────────┐
│         数据访问层 (Repository)       │
└─────────────────────────────────────┘
                 ↓
┌──────────────┬──────────────┬──────────────┐
│    MySQL     │    Redis     │ Elasticsearch │
│  (持久化存储)  │   (缓存)     │   (搜索)      │
└──────────────┴──────────────┴──────────────┘
```

**数据分类：**
1. **核心业务数据** → MySQL（用户、Agent、对话）
2. **热点数据** → Redis（Session、Token、计数器）
3. **搜索索引** → Elasticsearch（知识库、日志）
4. **向量数据** → Milvus（Embedding）
5. **文件对象** → MinIO（图片、文档）

### 4.4 缓存策略

**缓存层级：**
```
L1: 本地缓存（内存）
  ↓ L1 Miss
L2: Redis 缓存
  ↓ L2 Miss
L3: 数据库查询
```

**缓存场景：**

| 数据类型 | 缓存键 | TTL | 淘汰策略 |
|----------|--------|-----|----------|
| 用户 Session | `session:{userId}` | 7 天 | LRU |
| Agent 配置 | `agent:{botId}` | 1 小时 | LRU |
| API Token | `token:{tokenId}` | 30 天 | LRU |
| 热点对话 | `conversation:{convId}` | 1 小时 | LRU |
| 计数器 | `counter:{type}:{id}` | 永久 | 永不淘汰 |

## 5. 接口设计

### 5.1 API 设计原则

1. **RESTful 风格：** 资源导向，使用标准 HTTP 方法
2. **版本管理：** URL 版本号（如 `/api/v1/agents`）
3. **统一响应格式：** `code`, `message`, `data`, `requestId`
4. **错误码规范：** 5 位数字（如 40001）
5. **认证机制：** JWT Token + Personal Access Token

### 5.2 核心 API 定义

#### 5.2.1 Agent 管理 API

**创建 Agent**
```http
POST /api/v1/agents
Authorization: Bearer {token}
Content-Type: application/json

{
  "name": "客服助手",
  "description": "智能客服机器人",
  "avatar": "https://...",
  "systemPrompt": "你是一个专业的客服助手...",
  "modelConfig": {
    "model": "gpt-4",
    "temperature": 0.7,
    "maxTokens": 2048
  }
}

Response 201:
{
  "code": 0,
  "message": "success",
  "data": {
    "id": "bot_123456",
    "name": "客服助手",
    "createdAt": "2025-12-25T10:00:00Z"
  },
  "requestId": "req_abc123"
}
```

**发布 Agent**
```http
POST /api/v1/agents/{botId}/publish

{
  "version": "1.0.0",
  "changelog": "首次发布"

```

### 7.5 高可用方案（生产环境）

**MySQL 主从复制：**
```

    ↓ Binlog Replication
MySQL Slave 1 (Read) + MySQL Slave 2 (Read)
```

**Redis 哨兵模式：**
```
Redis Master
    ↓ Sentinel
Redis Slave 1 + Redis Slave 2
```

**Elasticsearch 集群：**
```
ES Node 1 (Master + Data)
ES Node 2 (Data + Ingest)
ES Node 3 (Data + Coordinating)
```

**负载均衡：**
```
Nginx LB → coze-server-1
         → coze-server-2
         → coze-server-3
```

### 7.6 备份与恢复

- 增量备份：每小时（Binlog）
- 备份保留：30 天
- 异地备份：每周同步到云端

**恢复目标：**
- RTO（恢复时间目标）≤ 1 小时
- RPO（恢复点目标）≤ 5 分钟
