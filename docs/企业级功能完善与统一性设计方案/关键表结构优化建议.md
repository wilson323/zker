## 1. Bot相关表优化

### 1.1 bots表 (Bot主表)

#### 🔍 当前设计分析

```sql
-- 当前设计(假设)
CREATE TABLE bots (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255),
    description TEXT,
    user_id BIGINT,
    status VARCHAR(50),
    created_at DATETIME,
    updated_at DATETIME
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

#### ❌ 存在的问题

1. **缺少租户隔离**: 无`tenant_id`字段
2. **字符集过时**: 使用`utf8`而非`utf8mb4`
3. **缺少约束**: 重要字段无`NOT NULL`约束
4. **缺少索引**: 外键字段`user_id`无索引
5. **命名不规范**: 表名应为复数`bots`已是正确,但字段可优化
6. **缺少软删除**: 无`deleted_at`字段

#### ✅ 优化后的设计

```sql
CREATE TABLE bots (
    -- 主键
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT 'Bot ID',

    -- 租户隔离(多租户SaaS必需)
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 基本信息
    name VARCHAR(255) NOT NULL COMMENT 'Bot名称',
    description TEXT COMMENT 'Bot描述',
    avatar_url VARCHAR(512) COMMENT '头像URL',

    -- 所有者
    creator_id BIGINT NOT NULL COMMENT '创建者ID',

    -- 状态字段
    status ENUM('draft', 'published', 'archived', 'deleted') NOT NULL DEFAULT 'draft' COMMENT '状态',
    version INT NOT NULL DEFAULT 1 COMMENT '版本号',

    -- 统计字段(反范式化,避免关联查询)
    conversation_count INT DEFAULT 0 COMMENT '对话数量',
    message_count INT DEFAULT 0 COMMENT '消息数量',
    follower_count INT DEFAULT 0 COMMENT '关注者数量',

    -- 软删除
    deleted_at DATETIME DEFAULT NULL COMMENT '删除时间',

    -- 审计字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    published_at DATETIME DEFAULT NULL COMMENT '发布时间',

    -- 唯一约束(同一租户下Bot名称唯一)
    UNIQUE KEY uk_tenant_name (tenant_id, name, deleted_at),

    -- 索引设计
    INDEX idx_tenant_id (tenant_id),                        -- 租户查询
    INDEX idx_creator_id (creator_id),                      -- 按创建者查询
    INDEX idx_status (status),                              -- 按状态查询
    INDEX idx_status_created (status, created_at DESC),     -- 复合索引: 状态+时间排序
    INDEX idx_tenant_status (tenant_id, status),            -- 租户+状态查询
    INDEX idx_follower_count (follower_count DESC),         -- 热门Bot排行

    -- 外键约束
    FOREIGN KEY (creator_id) REFERENCES users(id) ON DELETE RESTRICT

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Bot表';
```

#### 🎯 优化要点说明

**1. 租户隔离**
```sql
tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID'
```
- ✅ 多租户SaaS平台必需字段
- ✅ 应用层实现租户数据隔离
- ✅ 添加索引`idx_tenant_id`提升查询性能

**2. 反范式化统计字段**
```sql
conversation_count INT DEFAULT 0 COMMENT '对话数量',
message_count INT DEFAULT 0 COMMENT '消息数量',
follower_count INT DEFAULT 0 COMMENT '关注者数量'
```
- ⚠️ 反范式化字段,冗余但提升查询性能
- ✅ 通过触发器或应用层维护数据一致性
- ✅ 避免每次查询都JOIN统计表
- 💡 维护策略:
  - 触发器: INSERT/UPDATE时更新
  - 应用层: 在业务代码中更新
  - 定时任务: 每小时校准一次

**3. 复合索引设计**
```sql
INDEX idx_status_created (status, created_at DESC)
```
- ✅ 支持查询: `WHERE status = 'published' ORDER BY created_at DESC`
- ✅ 覆盖索引: 如果只查询id, name, status, created_at,无需回表
- ✅ 遵循最左前缀原则:
  - `WHERE status = ?` ✅ 使用索引
  - `WHERE created_at > ?` ❌ 不使用索引

**4. 软删除**
```sql
deleted_at DATETIME DEFAULT NULL
```
- ✅ 支持数据恢复
- ✅ 唯一约束包含`deleted_at`,允许同名Bot在删除后重新创建
- ✅ 查询时添加`WHERE deleted_at IS NULL`

**5. 字符集**
```sql
DEFAULT CHARSET=utf8mb4
```
- ✅ 支持emoji和特殊字符
- ✅ 完整的Unicode支持

### 1.2 bot_conversations表 (Bot对话表)

#### 🔍 当前设计分析

```sql
-- 当前设计(假设)
CREATE TABLE bot_conversations (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    bot_id BIGINT,
    user_id BIGINT,
    title VARCHAR(255),
    created_at DATETIME
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

#### ❌ 存在的问题

1. **缺少租户隔离**: 无`tenant_id`字段
2. **缺少统计字段**: 每次查询都要关联统计消息数
3. **缺少索引**: 外键字段无索引
4. **缺少状态字段**: 无法区分活跃/归档对话
5. **缺少软删除**: 无法恢复误删数据

#### ✅ 优化后的设计

```sql
CREATE TABLE bot_conversations (
    -- 主键
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '会话ID',

    -- 租户隔离
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 关联字段
    bot_id BIGINT NOT NULL COMMENT 'Bot ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',

    -- 基本信息
    title VARCHAR(255) DEFAULT '新对话' COMMENT '对话标题',

    -- 统计字段(反范式化,避免JOIN)
    message_count INT DEFAULT 0 COMMENT '消息数量',
    token_used INT DEFAULT 0 COMMENT 'Token使用量',

    -- 状态字段
    status ENUM('active', 'archived', 'deleted') NOT NULL DEFAULT 'active' COMMENT '状态',

    -- 软删除
    deleted_at DATETIME DEFAULT NULL COMMENT '删除时间',

    -- 审计字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

    -- 唯一约束(同一用户同一Bot同时只有一个活跃对话)
    UNIQUE KEY uk_tenant_bot_user_active (tenant_id, bot_id, user_id),
    CHECK (message_count >= 0),  -- MySQL 8.0.16+

    -- 索引设计
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_bot_id (bot_id),
    INDEX idx_user_id (user_id),
    INDEX idx_status_created (status, created_at DESC),
    INDEX idx_tenant_bot_user (tenant_id, bot_id, user_id),
    INDEX idx_tenant_status (tenant_id, status),

    -- 外键约束
    FOREIGN KEY (bot_id) REFERENCES bots(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Bot对话表';
```

#### 🎯 优化要点说明

**1. 反范式化统计字段**
```sql
message_count INT DEFAULT 0 COMMENT '消息数量',
token_used INT DEFAULT 0 COMMENT 'Token使用量'
```
- ✅ 避免每次查询都JOIN `bot_messages`表统计
- ✅ 提升查询性能: `SELECT * FROM bot_conversations ORDER BY message_count DESC`
- 💡 维护策略:
  - INSERT消息时: `UPDATE bot_conversations SET message_count = message_count + 1`
  - 删除消息时: `UPDATE bot_conversations SET message_count = message_count - 1`

**2. 唯一约束**
```sql
UNIQUE KEY uk_tenant_bot_user_active (tenant_id, bot_id, user_id)
```
- ⚠️ 不包含`deleted_at`,确保同一用户同一Bot同时只有一个对话
- ✅ 应用层在创建对话时检查: 如果存在活跃对话,返回或复用

**3. 复合索引**
```sql
INDEX idx_tenant_bot_user (tenant_id, bot_id, user_id)
```
- ✅ 支持查询: `WHERE tenant_id = ? AND bot_id = ? AND user_id = ?`
- ✅ 覆盖索引: 如果查询条件匹配索引前缀列

### 1.3 bot_messages表 (Bot消息表)

#### 🔍 当前设计分析

```sql
-- 当前设计(假设)
CREATE TABLE bot_messages (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    conversation_id BIGINT,
    content TEXT,
    role VARCHAR(20),
    created_at DATETIME
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

#### ❌ 存在的问题

1. **缺少租户隔离**: 无`tenant_id`字段
2. **角色字段不规范**: `role`应使用`ENUM`
3. **缺少Token统计**: 无法计算对话成本
4. **缺少索引**: 外键字段和查询字段无索引
5. **字符集**: 应使用`utf8mb4`

#### ✅ 优化后的设计

```sql
CREATE TABLE bot_messages (
    -- 主键
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '消息ID',

    -- 租户隔离
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 关联字段
    conversation_id BIGINT NOT NULL COMMENT '会话ID',
    bot_id BIGINT NOT NULL COMMENT 'Bot ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',

    -- 消息内容
    role ENUM('user', 'assistant', 'system') NOT NULL COMMENT '角色',
    content TEXT NOT NULL COMMENT '消息内容',
    content_type ENUM('text', 'image', 'audio', 'video', 'file') DEFAULT 'text' COMMENT '内容类型',

    -- 多模态数据
    attachments JSON COMMENT '附件列表(图片、文件等)',

    -- 元数据
    metadata JSON COMMENT '元数据(模型、温度、Tokens等)',

    -- Token统计
    prompt_tokens INT DEFAULT 0 COMMENT '输入Token数',
    completion_tokens INT DEFAULT 0 COMMENT '输出Token数',
    total_tokens INT DEFAULT 0 COMMENT '总Token数',

    -- 审计字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',

    -- 索引设计
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_conversation_id (conversation_id),              -- 查询对话的所有消息
    INDEX idx_bot_id (bot_id),
    INDEX idx_user_id (user_id),
    INDEX idx_created_at (created_at DESC),                   -- 时间排序
    INDEX idx_conversation_created (conversation_id, created_at DESC),  -- 复合索引

    -- 外键约束
    FOREIGN KEY (conversation_id) REFERENCES bot_conversations(id) ON DELETE CASCADE,
    FOREIGN KEY (bot_id) REFERENCES bots(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Bot消息表';
```

#### 🎯 优化要点说明

**1. 使用ENUM而非VARCHAR**
```sql
role ENUM('user', 'assistant', 'system') NOT NULL COMMENT '角色'
```
- ✅ 存储空间: 1-2字节 vs VARCHAR(20)的20+字节
- ✅ 数据完整性: 只能插入预定义的值
- ✅ 可读性: ENUM值直接可读

**2. Token统计字段**
```sql
prompt_tokens INT DEFAULT 0 COMMENT '输入Token数',
completion_tokens INT DEFAULT 0 COMMENT '输出Token数',
total_tokens INT DEFAULT 0 COMMENT '总Token数'
```
- ✅ 支持按对话统计成本
- ✅ 支持按用户/租户统计使用量
- ✅ 为计费系统提供数据基础

**3. JSON字段**
```sql
attachments JSON COMMENT '附件列表',
metadata JSON COMMENT '元数据'
```
- ✅ 灵活存储非结构化数据
- ✅ 支持JSON索引(MySQL 5.7.8+)
- 💡 使用示例:
  ```sql
  -- 查询包含图片附件的消息
  SELECT * FROM bot_messages
  WHERE JSON_CONTAINS(attachments, '{"type": "image"}');

  -- 查询使用特定模型的消息
  SELECT * FROM bot_messages
  WHERE JSON_EXTRACT(metadata, '$.model') = 'gpt-4';
  ```

**4. 复合索引**
```sql
INDEX idx_conversation_created (conversation_id, created_at DESC)
```
- ✅ 支持查询: `SELECT * FROM bot_messages WHERE conversation_id = ? ORDER BY created_at DESC`
- ✅ 覆盖索引: 如果只查询id, conversation_id, created_at,无需回表

## 2. 用户相关表优化

### 2.1 users表 (用户表)

#### ✅ 优化后的设计

```sql
CREATE TABLE users (
    -- 主键
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',

    -- 租户隔离
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 基本信息
    username VARCHAR(100) NOT NULL COMMENT '用户名',
    email VARCHAR(255) COMMENT '邮箱',
    phone VARCHAR(20) COMMENT '手机号',

    -- 认证信息
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
    salt VARCHAR(64) COMMENT '盐值',

    -- 状态字段
    status ENUM('active', 'inactive', 'banned', 'deleted') NOT NULL DEFAULT 'active' COMMENT '状态',

    -- 用户类型
    user_type ENUM('admin', 'user', 'guest') NOT NULL DEFAULT 'user' COMMENT '用户类型',

    -- 软删除
    deleted_at DATETIME DEFAULT NULL COMMENT '删除时间',

    -- 审计字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    last_login_at DATETIME COMMENT '最后登录时间',

    -- 唯一约束
    UNIQUE KEY uk_tenant_username (tenant_id, username, deleted_at),
    UNIQUE KEY uk_email (email),
    UNIQUE KEY uk_phone (phone),

    -- 索引设计
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_status (status),
    INDEX idx_user_type (user_type),
    INDEX idx_tenant_status (tenant_id, status),

    CHECK (email REGEXP '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$')  -- MySQL 8.0+

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

#### 🎯 优化要点说明

**1. 密码安全**
```sql
password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
salt VARCHAR(64) COMMENT '盐值'
```
- ✅ 使用`bcrypt`或`Argon2`哈希算法
- ✅ 不要存储明文密码
- ✅ 盐值防止彩虹表攻击

**2. 唯一约束**
```sql
UNIQUE KEY uk_tenant_username (tenant_id, username, deleted_at),
UNIQUE KEY uk_email (email),
UNIQUE KEY uk_phone (phone)
```
- ✅ 用户名在同一租户下唯一(包含deleted_at支持删除后重建)
- ✅ 邮箱和手机号全局唯一

**3. CHECK约束**
```sql
CHECK (email REGEXP '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$')
```
- ✅ 确保邮箱格式正确
- ✅ 应用层也应验证

## 3. 商业化相关表优化

### 3.1 subscriptions表 (订阅表)

#### ✅ 优化后的设计

```sql
CREATE TABLE subscriptions (
    -- 主键
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '订阅ID',

    -- 租户隔离
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 关联字段
    user_id BIGINT NOT NULL COMMENT '用户ID',
    plan_id BIGINT NOT NULL COMMENT '套餐ID',

    -- 订阅状态
    status ENUM('active', 'expired', 'cancelled', 'pending') NOT NULL DEFAULT 'pending' COMMENT '状态',

    -- 时间范围
    started_at DATETIME NOT NULL COMMENT '开始时间',
    expires_at DATETIME NOT NULL COMMENT '过期时间',
    cancelled_at DATETIME DEFAULT NULL COMMENT '取消时间',

    -- 支付信息
    payment_method ENUM('alipay', 'wechat', 'credit_card', 'paypal') COMMENT '支付方式',
    payment_id VARCHAR(100) COMMENT '支付ID',

    -- 自动续费
    auto_renew BOOLEAN DEFAULT FALSE COMMENT '是否自动续费',

    -- 金额(快照,避免历史数据变更)
    amount DECIMAL(10, 2) NOT NULL COMMENT '订阅金额',
    currency VARCHAR(10) DEFAULT 'CNY' COMMENT '货币',

    -- 审计字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

    -- 唯一约束(一个用户同时只有一个活跃订阅)
    UNIQUE KEY uk_user_active (user_id, status),
    CHECK (amount > 0),

    -- 索引设计
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_user_id (user_id),
    INDEX idx_status (status),
    INDEX idx_expires_at (expires_at),
    INDEX idx_status_expires (status, expires_at),  -- 查询即将过期的订阅
    INDEX idx_auto_renew (auto_renew),             -- 查询需要自动续费的订阅

    -- 外键约束
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (plan_id) REFERENCES subscription_plans(id) ON DELETE RESTRICT

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订阅表';
```

#### 🎯 优化要点说明

**1. 唯一约束**
```sql
UNIQUE KEY uk_user_active (user_id, status)
```
- ⚠️ 仅在status='active'时唯一
- ✅ 确保一个用户同时只有一个活跃订阅
- 💡 插入时逻辑:
  ```sql
  -- 创建新订阅前,先取消旧订阅
  UPDATE subscriptions SET status = 'cancelled' WHERE user_id = ? AND status = 'active';
  INSERT INTO subscriptions (...) VALUES (...);
  ```

**2. 复合索引**
```sql
INDEX idx_status_expires (status, expires_at)
```
- ✅ 支持查询: `WHERE status = 'active' AND expires_at < NOW() + INTERVAL 7 DAY`
- ✅ 用于自动续费任务查询即将过期的订阅

**3. 金额快照**
```sql
amount DECIMAL(10, 2) NOT NULL COMMENT '订阅金额'
```
- ✅ 存储订阅时的金额快照
- ✅ 即使套餐价格变更,历史记录不变

### 3.2 bot_store_listings表 (Bot商店条目表)

#### ✅ 优化后的设计

```sql
CREATE TABLE bot_store_listings (
    -- 主键
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '条目ID',

    -- 租户隔离
    tenant_id VARCHAR(64) NOT NULL COMMENT '租户ID',

    -- 关联字段
    bot_id BIGINT NOT NULL COMMENT 'Bot ID',

    -- 商店信息
    listing_title VARCHAR(255) NOT NULL COMMENT '商店展示标题',
    description TEXT COMMENT '详细描述',
    long_description LONGTEXT COMMENT '富文本详情',
    screenshots JSON COMMENT '截图列表(URL数组)',
    video_url VARCHAR(512) COMMENT '演示视频URL',

    -- 分类与标签
    category VARCHAR(100) COMMENT '一级分类',
    subcategory VARCHAR(100) COMMENT '二级分类',
    tags JSON COMMENT '标签数组',

    -- 定价
    pricing_type ENUM('free', 'paid', 'freemium') DEFAULT 'free' COMMENT '定价类型',
    price DECIMAL(10, 2) COMMENT '价格(付费Bot)',

    -- 统计字段(反范式化,提升查询性能)
    view_count INT DEFAULT 0 COMMENT '浏览次数',
    clone_count INT DEFAULT 0 COMMENT '复克次数',
    download_count INT DEFAULT 0 COMMENT '下载次数',
    rating_avg DECIMAL(3, 2) COMMENT '平均评分',
    rating_count INT DEFAULT 0 COMMENT '评价数量',

    -- 状态字段
    status ENUM('draft', 'pending_review', 'published', 'rejected', 'suspended') NOT NULL DEFAULT 'draft' COMMENT '状态',
    featured BOOLEAN DEFAULT FALSE COMMENT '是否精选',
    verified BOOLEAN DEFAULT FALSE COMMENT '是否官方认证',

    -- 提交信息
    submitter_id BIGINT NOT NULL COMMENT '提交者ID',
    submitted_at DATETIME COMMENT '提交时间',
    reviewed_at DATETIME COMMENT '审核时间',
    reviewer_id BIGINT COMMENT '审核人ID',
    reject_reason TEXT COMMENT '拒绝原因',

    -- 审计字段
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    published_at DATETIME COMMENT '发布时间',

    -- 唯一约束(一个Bot只能发布一次)
    UNIQUE KEY uk_bot (bot_id),

    -- 索引设计
    INDEX idx_tenant_id (tenant_id),
    INDEX idx_status (status),
    INDEX idx_category (category),
    INDEX idx_featured_status (featured, status),           -- 首页精选Bot
    INDEX idx_clone_count (clone_count DESC),               -- 热门Bot排行
    INDEX idx_rating_avg (rating_avg DESC),                 -- 高分Bot排行
    INDEX idx_created_at (created_at DESC),                 -- 最新Bot
    INDEX idx_tenant_status (tenant_id, status),            -- 租户的Bot列表

    -- 全文索引(搜索)
    FULLTEXT INDEX ft_title_description_tags (listing_title, description, tags) WITH PARSER ngram,

    -- 外键约束
    FOREIGN KEY (bot_id) REFERENCES bots(id) ON DELETE CASCADE,
    FOREIGN KEY (submitter_id) REFERENCES users(id) ON DELETE RESTRICT,
    FOREIGN KEY (reviewer_id) REFERENCES users(id) ON DELETE SET NULL

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='Bot商店条目表';
```

#### 🎯 优化要点说明

**1. 反范式化统计字段**
```sql
view_count INT DEFAULT 0 COMMENT '浏览次数',
clone_count INT DEFAULT 0 COMMENT '复克次数',
rating_avg DECIMAL(3, 2) COMMENT '平均评分'
```
- ⚠️ 冗余字段,避免每次查询都JOIN统计表
- ✅ 大幅提升首页和详情页查询性能
- 💡 维护策略:
  ```sql
  -- 浏览+1
  UPDATE bot_store_listings SET view_count = view_count + 1 WHERE id = ?;

  -- 复克+1
  UPDATE bot_store_listings SET clone_count = clone_count + 1 WHERE id = ?;

  -- 评价后更新评分
  UPDATE bot_store_listings l
  SET rating_avg = (
    SELECT AVG(rating) FROM bot_store_reviews WHERE listing_id = l.id
  ),
  rating_count = (
    SELECT COUNT(*) FROM bot_store_reviews WHERE listing_id = l.id
  )
  WHERE l.id = ?;
  ```

**2. 复合索引**
```sql
INDEX idx_featured_status (featured, status)
```
- ✅ 支持查询: `SELECT * FROM bot_store_listings WHERE featured = TRUE AND status = 'published'`
- ✅ 用于首页"精选Bot"列表

**3. 全文索引**
```sql
FULLTEXT INDEX ft_title_description_tags (listing_title, description, tags) WITH PARSER ngram
```
- ✅ 支持中文全文搜索
- ✅ 查询示例:
  ```sql
  SELECT *,
    MATCH(listing_title, description, tags) AGAINST('客服机器人' IN BOOLEAN MODE) AS score
  FROM bot_store_listings
  WHERE MATCH(listing_title, description, tags) AGAINST('客服机器人' IN BOOLEAN MODE)
  ORDER BY score DESC;
  ```

**4. JSON字段**
```sql
screenshots JSON COMMENT '截图列表(URL数组)',
tags JSON COMMENT '标签数组'
```
- ✅ 灵活存储数组数据
- 💡 使用示例:
  ```sql
  -- 查询包含特定标签的Bot
  SELECT * FROM bot_store_listings
  WHERE JSON_CONTAINS(tags, '"客服"');

  -- 添加标签
  UPDATE bot_store_listings
  SET tags = JSON_ARRAY_APPEND(tags, '$', 'AI');
  ```

## 5. 性能优化建议总结

### 5.1 反范式化决策

**何时使用反范式化**:
```
✅ 读多写少场景 (读写比 > 10:1)
✅ 性能瓶颈无法通过索引优化解决
✅ 数据一致性维护成本可接受
✅ 有明确的业务理由

❌ 写多读少场景
❌ 数据一致性要求极高
❌ 维护成本过高
```

**示例**:
```sql
-- ✅ 合理反范式化
view_count INT DEFAULT 0 COMMENT '浏览次数' -- 读多写少,性能提升明显

-- ❌ 不合理反范式化
user_email VARCHAR(255) COMMENT '用户邮箱' -- 应通过user_id关联查询
```

### 5.2 索引优化清单

```sql
-- 1. 所有外键字段必须有索引
INDEX idx_bot_id (bot_id)
INDEX idx_user_id (user_id)

-- 2. WHERE条件字段应有索引
INDEX idx_status (status)

-- 3. ORDER BY字段应有索引
INDEX idx_created_at (created_at DESC)

-- 4. 复合索引遵循最左前缀原则
INDEX idx_status_created (status, created_at DESC)

-- 5. 覆盖索引避免回表
INDEX idx_user_status_created_id (user_id, status, created_at, id)
```

### 5.3 字符集选择

```sql
-- ✅ 推荐
DEFAULT CHARSET=utf8mb4  -- 支持emoji和完整Unicode

-- ❌ 避免
DEFAULT CHARSET=utf8     -- 不支持emoji
DEFAULT CHARSET=latin1   -- 只支持ASCII
```

### 5.4 时间字段选择

```sql
-- ✅ 业务时间使用DATETIME
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP

-- ✅ 日志时间可使用TIMESTAMP
logged_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```
