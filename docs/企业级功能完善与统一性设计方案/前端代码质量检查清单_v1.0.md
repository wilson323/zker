## ✅ 1. 设计令牌使用检查

### 颜色使用
- [ ] 禁止硬编码颜色值（如 `#1890ff`, `red`, `rgb(0,0,0)`）
- [ ] 必须使用 `designTokens.colors.*`
- [ ] 正确使用颜色层级（primary[1-10]、success[1-10] 等）

### 间距使用
- [ ] 禁止硬编码间距值（如 `padding: 16px`）
- [ ] 必须使用 `designTokens.spacing.*`
- [ ] 保持 4px/8px 基准对齐

### 圆角使用
- [ ] 禁止硬编码圆角值（如 `border-radius: 8px`）
- [ ] 必须使用 `designTokens.borderRadius.*`

### 阴影使用
- [ ] 禁止硬编码阴影值
- [ ] 必须使用 `designTokens.shadows.*`

## ✅ 2. 组件设计规范检查

### SOLID 原则

**单一职责（S）**
- [ ] 组件只做一件事
- [ ] 组件文件行数 < 300行
- [ ] Props 数量 < 10个（使用对象合并过多参数）

**开放封闭（O）**
- [ ] 通过 Props 扩展功能
- [ ] 避免修改现有组件代码
- [ ] 使用 composition 而非继承

**依赖倒置（D）**
- [ ] 依赖 Props 接口抽象
- [ ] 不依赖具体实现类

### DRY 原则
- [ ] 无重复代码
- [ ] 相似逻辑抽取为 hooks
- [ ] 相似样式抽取为公共类

### YAGNI 原则
- [ ] 只实现当前需要的功能
- [ ] 移除未使用的代码
- [ ] 避免过度设计

## ✅ 3. TypeScript 规范检查

### 类型定义
- [ ] 无 `any` 类型（除非有明确注释）
- [ ] 所有函数参数都有类型
- [ ] 所有返回值都有类型
- [ ] 使用 interface 或 type 定义对象结构

### 组件 Props
- [ ] Props 接口完整导出
- [ ] 可选参数使用 `?` 标记
- [ ] 提供默认值使用 `=`
- [ ] 复杂类型使用 `type` 提取

### 导出规范
```typescript
// ✅ Good
export interface ButtonProps {
  type?: 'primary' | 'secondary' | 'danger';
  size?: 'small' | 'default' | 'large';
  children?: React.ReactNode;
}

// ❌ Bad
export interface ButtonProps {
  type?: any;
  size?: any;
}
```

## ✅ 10. Git 提交规范

### Commit Message
```bash
# 格式
<type>(<scope>): <subject>

<body>

<footer>

# 类型
feat: 新功能
fix: Bug修复
docs: 文档更新
style: 代码格式（不影响功能）
refactor: 重构
perf: 性能优化
test: 测试相关
chore: 构建/工具配置

# 示例
feat(ui-components): add Card component with hoverable prop
fix(api-client): resolve tenant list pagination bug
docs(readme): update installation instructions
```
