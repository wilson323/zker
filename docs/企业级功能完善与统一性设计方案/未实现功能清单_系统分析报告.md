## 🔧 开发规范要求

### 1. 架构规范

- **DDD分层架构**: domain → application → api → infra
- **依赖方向**: 高层依赖低层，依赖倒置
- **接口隔离**: 领域层定义接口，基础设施层实现

### 2. 编码规范

**Go代码规范**:
- 包命名：小写单词，不使用下划线
- 接口命名：动词+名词，以`er`或`or`结尾
- 错误处理：使用自定义错误类型，始终处理错误
- 日志：使用结构化日志，包含请求追踪ID

**TypeScript代码规范**:
- 组件命名：PascalCase
- 文件命名：kebab-case或PascalCase（组件）
- 类型定义：优先使用interface
- Hooks：以`use`开头，遵循React Hooks规则

### 3. 数据库规范

- 表命名：小写+下划线，多对多关系表使用`_`连接
- 字段命名：小写+下划线
- 索引命名：`idx_表名_字段名`
- 外键命名：`fk_表名_字段名`
- 所有表必须包含：`id`, `created_at`, `updated_at`, `deleted_at`

### 4. API规范

- RESTful风格：GET（查询）、POST（创建）、PUT（更新）、DELETE（删除）
- URL命名：小写+连字符，复数名词
- 响应格式：统一JSON格式，包含code、message、data
- 错误码：使用HTTP状态码+业务错误码

### 5. 测试规范

- 单元测试覆盖率：Level 1 ≥80%，Level 2 ≥30%
- 集成测试：关键业务流程必须有集成测试
- E2E测试：核心用户流程必须有E2E测试
