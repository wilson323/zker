## 1. 设计概述

### 1.1 建设目标

为zker Enterprise项目团队构建一个**企业级知识库系统**，实现：

1. **知识沉淀**: 将个人经验转化为组织资产，降低人员流动风险
2. **知识共享**: 促进团队成员间的知识交流与协作
3. **快速检索**: 基于AI的智能搜索，快速找到所需知识
4. **持续学习**: 个性化推荐，助力员工技能提升
5. **知识创新**: 激发团队创新活力，提升组织竞争力

### 1.2 核心价值

- **降低Onboarding时间**: 新员工从3个月缩短至**1个月**
- **减少重复沟通**: 常见问题自助查询，减少**30%**重复咨询
- **提升问题解决效率**: 相似问题参考历史案例，解决速度提升**50%**
- **传承组织智慧**: 关键知识永不流失，形成组织记忆

### 1.3 设计原则

- **以用户为中心**: 知识库服务于团队日常工作和学习
- **持续沉淀**: 鼓励知识分享，将知识沉淀融入日常工作流
- **质量优先**: 知识质量重于数量，建立审核机制
- **易于维护**: 知识库需要长期维护，设计要考虑可持续性
- **安全可控**: 知识分级管理，敏感知识保护

#### 5.1.2 智能搜索

**功能需求**: KB-FUNC-007 ~ KB-FUNC-011

**设计要点**:

1. **全文检索**:
   - 使用`Elasticsearch`或`Meilisearch`
   - 索引知识标题、内容、标签
   - 支持中文分词（jieba）
   - 支持模糊搜索（容错）

2. **语义搜索**:
   - 使用`Embedding模型`（text-embedding-ada-002）
   - 将查询和知识向量化
   - 计算余弦相似度
   - 返回Top-K相关知识

3. **搜索增强**:
   - 搜索结果高亮
   - 搜索建议（自动补全）
   - 相关搜索推荐
   - 搜索历史记录

**技术实现**:

```python
# 语义搜索实现示例
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity

# 加载Embedding模型
model = SentenceTransformer('shibing624/text-embedding-ada-002')

# 知识库向量化
knowledge_base = [
    "Multi-Tenant数据隔离方案",
    "工作流引擎架构设计",
    "Go语言DDD分层架构实践"
]
embeddings = model.encode(knowledge_base)

# 查询向量化
query = "如何实现租户隔离？"
query_embedding = model.encode([query])

# 计算相似度
similarities = cosine_similarity(query_embedding, embeddings)

# 返回Top-3
top_k_indices = similarities.argsort()[0][-3:][::-1]
for i, idx in enumerate(top_k_indices):
    print(f"第{i+1}名: {knowledge_base[idx]} (相似度: {similarities[0][idx]:.2f})")
```

**Bug分析模板**:

```markdown
# Bug分析报告 - 租户数据泄露漏洞

## Bug信息
- Bug ID: BUG-2025-001
- 发现时间: 2025-12-26 10:30
- 严重程度: 严重 (P0)
- 发现人: 测试工程师李四

## Bug描述
用户可以通过修改URL参数查看其他租户的数据

## 复现步骤
1. 用户A登录，获取access_token
2. 修改API请求头: X-Tenant-ID: tenant_b
3. 调用GET /api/v1/bots
4. 成功返回租户B的Bot列表

## 影响范围
- 租户数据隔离失效
- 可能导致数据泄露
- 安全合规风险

## 根因分析
1. 代码审查发现: API handler中未验证租户ID
2. 问题代码: `handler.go:145`
   ```go
   tenantID := c.Query("tenant_id")
   // 缺少验证当前用户是否有权访问该租户
   ```
3. 根本原因: 缺少租户权限验证中间件

## 解决方案
1. 修复代码: 添加租户权限验证
2. 添加中间件: `TenantAccessMiddleware`
3. 完善单元测试: 覆盖租户隔离场景
4. 回归测试: 验证修复有效

## 预防措施
1. 代码审查清单增加"租户隔离检查项"
2. 自动化测试: 增加租户隔离测试用例
3. 安全培训: 开发团队安全意识培训

## 经验教训
1. 租户隔离是核心安全特性，必须100%覆盖测试
2. 代码审查不能流于形式，要深入检查安全逻辑
3. 安全左移: 在设计阶段就要考虑安全
```

### 8.3 数据模型

#### 8.3.1 知识表

```sql
CREATE TABLE knowledge (
  id VARCHAR(64) PRIMARY KEY,
  tenant_id VARCHAR(64) NOT NULL,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  category VARCHAR(64) NOT NULL,
  subcategory VARCHAR(64),
  tags JSON,
  author_id VARCHAR(64),
  author_name VARCHAR(128),
  role VARCHAR(64),
  difficulty VARCHAR(32),
  status VARCHAR(32) DEFAULT 'draft',
  content_type VARCHAR(32),
  content TEXT,
  content_json JSON,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  -- 统计信息
  views INT DEFAULT 0,
  likes INT DEFAULT 0,
  favorites INT DEFAULT 0,
  comments_count INT DEFAULT 0,
  rating DECIMAL(3,2) DEFAULT 0.00,

  -- 质量评估
  quality_score DECIMAL(3,2),
  expert_approved BOOLEAN DEFAULT FALSE,
  last_reviewed_at TIMESTAMP,

  -- 索引
  FULLTEXT INDEX idx_fulltext (title, content),
  INDEX idx_tenant_id (tenant_id),
  INDEX idx_category (category),
  INDEX idx_status (status),
  INDEX idx_created_at (created_at)
);

CREATE TABLE knowledge_tags (
  id VARCHAR(64) PRIMARY KEY,
  tenant_id VARCHAR(64) NOT NULL,
  tag_name VARCHAR(64) NOT NULL,
  category VARCHAR(64),
  usage_count INT DEFAULT 0,
  INDEX idx_tenant_tag (tenant_id, tag_name)
);

CREATE TABLE knowledge_relations (
  id VARCHAR(64) PRIMARY KEY,
  tenant_id VARCHAR(64) NOT NULL,
  source_knowledge_id VARCHAR(64),
  target_knowledge_id VARCHAR(64),
  relation_type VARCHAR(32), -- related, reference, depends
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_source (source_knowledge_id),
  INDEX idx_target (target_knowledge_id),
  UNIQUE KEY uk_source_target (source_knowledge_id, target_knowledge_id, relation_type)
);

CREATE TABLE knowledge_comments (
  id VARCHAR(64) PRIMARY KEY,
  tenant_id VARCHAR(64) NOT NULL,
  knowledge_id VARCHAR(64) NOT NULL,
  user_id VARCHAR(64),
  user_name VARCHAR(128),
  content TEXT NOT NULL,
  parent_id VARCHAR(64),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_knowledge_id (knowledge_id),
  INDEX idx_user_id (user_id)
);
```
