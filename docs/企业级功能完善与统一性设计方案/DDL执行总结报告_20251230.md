## 🗄️ 表结构设计

### 1. tenants（租户表）

**字段数量**: 13
**索引数量**: 6
**外键约束**: 无（主表）

**核心字段**:
```sql
tenant_id          VARCHAR(36)  PRIMARY KEY
tenant_name        VARCHAR(200) NOT NULL
tenant_type        ENUM         NOT NULL
status             ENUM         NOT NULL
subscription_tier  ENUM         NOT NULL
contact_email      VARCHAR(255)
settings           JSON
created_at         BIGINT       NOT NULL
updated_at         BIGINT       NOT NULL
deleted_at         BIGINT
```

**索引设计**:
- PRIMARY KEY: tenant_id
- UNIQUE INDEX: uk_tenant_name (tenant_name, deleted_at)
- INDEX: idx_tenant_type, idx_status, idx_subscription_tier, idx_created_at

### 2. subscriptions（订阅表）

**字段数量**: 14
**索引数量**: 5
**外键约束**: 1个（tenant_id → tenants）

**核心字段**:
```sql
subscription_id           VARCHAR(36)  PRIMARY KEY
tenant_id                 VARCHAR(36)  FOREIGN KEY
plan_tier                 ENUM         NOT NULL
billing_cycle             ENUM         NOT NULL
start_date                DATE         NOT NULL
end_date                  DATE
quota_bots                INT          NOT NULL
quota_messages_per_month  INT          NOT NULL
quota_storage_gb          INT          NOT NULL
quota_team_members        INT          NOT NULL
auto_renew                BOOLEAN      NOT NULL
status                    ENUM         NOT NULL
```

**索引设计**:
- PRIMARY KEY: subscription_id
- FOREIGN KEY: tenant_id → tenants(tenant_id)
- UNIQUE INDEX: uk_tenant_plan (tenant_id, plan_tier)
- INDEX: idx_tenant_id, idx_plan_tier, idx_status, idx_end_date

### 3. quotas（配额表）

**字段数量**: 10
**索引数量**: 3
**外键约束**: 1个（tenant_id → tenants）

**核心字段**:
```sql
quota_id       VARCHAR(36)  PRIMARY KEY
tenant_id      VARCHAR(36)  FOREIGN KEY
resource_type  ENUM         NOT NULL
max_limit      INT          NOT NULL
used_count     INT          NOT NULL
reset_cycle    ENUM         NOT NULL
last_reset_at  BIGINT       NOT NULL
```

**索引设计**:
- PRIMARY KEY: quota_id
- FOREIGN KEY: tenant_id → tenants(tenant_id)
- UNIQUE INDEX: uk_tenant_resource (tenant_id, resource_type)
- INDEX: idx_tenant_resource

### 4. quota_usage_log（配额使用日志表）

**字段数量**: 12
**索引数量**: 4
**外键约束**: 1个（tenant_id → tenants）

**核心字段**:
```sql
log_id         BIGINT       AUTO_INCREMENT PRIMARY KEY
tenant_id      VARCHAR(36)  FOREIGN KEY
resource_type  ENUM         NOT NULL
resource_id    VARCHAR(36)
action         ENUM         NOT NULL
amount         INT          NOT NULL
before_count   INT          NOT NULL
after_count    INT          NOT NULL
request_id     VARCHAR(36)
user_id        VARCHAR(36)
reason         VARCHAR(500)
```

**索引设计**:
- PRIMARY KEY: log_id (AUTO_INCREMENT)
- FOREIGN KEY: tenant_id → tenants(tenant_id)
- INDEX: idx_tenant_resource, idx_created_at, idx_user_id

## 🎯 触发器设计

### 1. trg_tenant_status_update

**触发时机**: BEFORE UPDATE ON `tenants`

**功能**:
1. **租户暂停**（active → suspended）
   - 自动暂停所有订阅
   - 记录配额使用日志

2. **租户恢复**（suspended → active）
   - 恢复未过期的订阅
   - 智能判断订阅有效性

### 2. trg_quota_update_timestamp

**触发时机**: BEFORE UPDATE ON `quotas`

**功能**:
- 当used_count变化时，自动更新updated_at时间戳
- 确保配额变更的时间准确性

## 📊 视图设计

### 1. v_tenant_statistics（租户统计视图）

**查询字段**: 15
**数据源**: tenants、subscriptions、bots、space_users、quotas

**核心功能**:
- 租户基本信息
- 订阅信息
- Bot数量统计
- 用户统计
- 配额使用情况

**使用示例**:
```sql
SELECT * FROM v_tenant_statistics WHERE tenant_id = 'system-default';
```

### 2. v_quota_usage_rate（配额使用率视图）

**查询字段**: 8
**数据源**: quotas、tenants

**核心功能**:
- 计算配额使用率百分比
- 识别配额接近满额的租户
- 支持告警和预警

**使用示例**:
```sql
SELECT * FROM v_quota_usage_rate
WHERE usage_rate > 80
ORDER BY usage_rate DESC;
```

### 3. v_subscription_expiry_alert（订阅到期提醒视图）

**查询字段**: 9
**数据源**: subscriptions、tenants

**核心功能**:
- 监控订阅到期情况
- 三级告警（critical/warning/normal）
- 自动续费提醒

**告警规则**:
- **critical**: 距离到期 ≤ 7天
- **warning**: 距离到期 ≤ 30天
- **normal**: 其他

## ✅ 质量保证

### 1. 命名规范

✅ **表名**: 小写复数（tenants、subscriptions、quotas）
✅ **主键**: `{table}_id`（tenant_id、subscription_id）
✅ **外键**: `{referenced_table}_id`（tenant_id）
✅ **布尔字段**: `is_{property}`（未使用，全部用status枚举）
✅ **时间戳**: `{action}_at`（created_at、updated_at、deleted_at）
✅ **枚举类型**: 使用ENUM（status、tenant_type、resource_type）

### 2. 索引设计

✅ **所有主键**: 自动创建PRIMARY KEY索引
✅ **所有外键**: 创建普通索引
✅ **高频查询字段**: 创建独立索引（status、tenant_type）
✅ **唯一约束**: 使用UNIQUE INDEX
✅ **复合索引**: 遵循最左前缀原则

### 3. 数据完整性

✅ **外键约束**: 完整的外键级联（ON DELETE CASCADE）
✅ **非空约束**: 核心字段NOT NULL
✅ **默认值**: 合理的默认值设置
✅ **枚举类型**: 严格的数据类型限制
✅ **软删除**: 使用deleted_at而非硬删除

### 4. 性能优化

✅ **索引优化**: 所有外键和查询字段都有索引
✅ **查询优化**: 使用视图简化复杂查询
✅ **数据类型**: 使用最合适的数据类型（VARCHAR(36)存储UUID）
✅ **时间戳**: 使用BIGINT存储毫秒时间戳

## 🚀 部署流程

### 开发环境

```bash
cd backend/scripts

# 设置环境变量
export MYSQL_HOST=localhost
export MYSQL_PORT=3306
export MYSQL_USER=root
export MYSQL_PASSWORD=your_password

# 执行自动化部署
chmod +x test_tenant_ddl.sh
./test_tenant_ddl.sh
```

### 生产环境

```bash
# 1. 备份数据库
mysqldump -u root -p opencoze > backup_$(date +%Y%m%d).sql

# 2. 执行DDL（按顺序）
mysql -u root -p opencoze < docker/atlas/migrations/20251230025000_create_tenant_tables.sql
mysql -u root -p opencoze < docker/atlas/migrations/20251230025001_tenant_status_trigger.sql
mysql -u root -p opencoze < docker/atlas/migrations/20251230025002_tenant_statistics_view.sql
mysql -u root -p opencoze < docker/atlas/migrations/20251230025003_init_tenant_data.sql

# 3. 验证部署
mysql -u root -p opencoze < backend/scripts/verify_tenant_ddl.sql

# 4. 运行集成测试
cd backend/scripts
go run test_tenant_integration.go -host=localhost -port=3306 -user=root -password=$MYSQL_PASSWORD
```
