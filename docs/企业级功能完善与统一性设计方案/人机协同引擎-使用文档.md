## 1. 快速开始

### 1.1 数据库初始化

执行SQL脚本创建所需的数据库表：

```bash
mysql -u root -p < backend/conf/sql/humaninloop/001_create_collaboration_tables.sql
```

### 1.2 配置初始化

创建租户配置（系统会自动使用默认值）：

```sql
INSERT INTO collaboration_configs (
    tenant_id,
    auto_review_threshold,
    auto_escalate_threshold,
    default_sla_minutes,
    urgent_sla_minutes
) VALUES (
    'tenant-001',
    0.70,
    0.30,
    60,
    15
);
```

### 1.3 创建第一个审核任务

```go
// 创建任务请求
req := &CreateTaskRequest{
    TenantID: "tenant-001",
    TaskType: TaskTypeReview,
    Source:   SourceAI,
    Priority: PriorityMedium,
    Context: map[string]interface{}{
        "bot_id":   "bot-123",
        "bot_name": "My Bot",
        "content":  "需要审核的内容",
    },
    TriggerReason: "AI置信度低于阈值",
}

// 创建任务
task, err := orchestrator.CreateTask(ctx, req)
if err != nil {
    log.Fatal(err)
}

fmt.Printf("任务创建成功: %s\n", task.TaskID)
```

## 2. 核心概念

### 2.1 任务类型 (TaskType)

| 类型 | 说明 | 使用场景 |
|------|------|---------|
| `REVIEW` | 内容审核 | Bot发布、工作流发布 |
| `CORRECTION` | 错误修正 | 工作流执行错误 |
| `VALIDATION` | 决策验证 | AI决策置信度低 |
| `ESCALATION` | 问题升级 | SLA超时、复杂问题 |

### 2.2 任务优先级 (Priority)

| 优先级 | 说明 | SLA建议 |
|--------|------|---------|
| `LOW` | 低优先级 | 4小时 |
| `MEDIUM` | 中优先级 | 1小时 |
| `HIGH` | 高优先级 | 30分钟 |
| `URGENT` | 紧急 | 15分钟 |

### 2.3 任务状态流转

```
PENDING → ASSIGNED → IN_PROGRESS → COMPLETED
                ↓
            ESCALATED
                ↓
            CANCELLED
```

## 3. API使用指南

### 3.1 创建协同任务

**接口**: `POST /api/human-in-loop/tasks`

**请求**:
```json
{
  "task_type": "REVIEW",
  "source": "AI",
  "priority": "MEDIUM",
  "context": {
    "bot_id": "bot-123",
    "bot_name": "My Bot"
  },
  "trigger_reason": "AI置信度低于阈值",
  "assign_to": "user-001",
  "sla_minutes": 60
}
```

**响应**:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "task_id": "task-abc-123",
    "status": "PENDING",
    "created_at": 1704302400000
  }
}
```

### 3.2 获取任务列表

**接口**: `GET /api/human-in-loop/tasks`

**查询参数**:
- `page`: 页码（默认1）
- `page_size`: 每页数量（默认20）
- `status`: 状态过滤
- `priority`: 优先级过滤
- `assigned_to`: 审核人过滤

**请求**:
```bash
GET /api/human-in-loop/tasks?page=1&page_size=20&status=PENDING
```

### 3.3 分配任务

**接口**: `POST /api/human-in-loop/tasks/{task_id}/assign`

**请求**:
```json
{
  "assign_to": "user-002",
  "reason": "重新分配"
}
```

### 3.4 提交审核结果

**接口**: `POST /api/human-in-loop/tasks/{task_id}/review`

**请求**:
```json
{
  "decision": "approved",
  "human_decision": {
    "approved": true,
    "comment": "内容符合要求"
  },
  "decision_reason": "质量良好"
}
```

**决策类型**:
- `approved`: 通过
- `rejected`: 拒绝
- `modified`: 修改

### 3.5 升级任务

**接口**: `POST /api/human-in-loop/tasks/{task_id}/escalate`

**请求**:
```json
{
  "escalate_to": "admin-001",
  "reason": "需要高级审核"
}
```

## 4. 业务集成示例

### 4.1 Bot创建审核集成

```go
// 在 BotService 中集成
func (s *BotService) CreateBot(ctx context.Context, req *CreateBotRequest) (*Bot, error) {
    // 1. 创建Bot（草稿）
    bot := &Bot{
        Name:   req.Name,
        Status: "draft",
        // ...
    }

    if err := s.repo.Create(ctx, bot); err != nil {
        return nil, err
    }

    // 2. 触发人工审核
    task, err := s.reviewService.CreateBotWithReview(ctx, bot, 0.65)
    if err != nil {
        return nil, err
    }

    // 3. 关联任务
    bot.ReviewTaskID = &task.TaskID

    return bot, nil
}
```

### 4.2 敏感内容检测集成

```go
// 在消息处理中集成
func (s *MessageService) ProcessMessage(ctx context.Context, msg *Message) error {
    // 检测敏感内容
    if err := s.reviewService.CheckAndReviewSensitiveContent(
        ctx,
        msg.ConversationID,
        msg.MessageID,
        msg.Content,
    ); err != nil {
        return err
    }

    return nil
}
```

### 4.3 工作流错误修正集成

```go
// 在工作流执行中集成
func (s *WorkflowService) Execute(ctx context.Context, workflowID string) error {
    // 执行工作流
    result, err := s.executor.Execute(ctx, workflowID)
    if err != nil {
        // 触发人工修正
        return s.reviewService.CorrectWorkflowError(
            ctx,
            workflowID,
            err.Error(),
            map[string]interface{}{
                "node_id":   err.NodeID,
                "error_type": err.Type,
            },
        )
    }

    return nil
}
```

## 5. 配置说明

### 5.1 租户配置

```sql
-- 查看配置
SELECT * FROM collaboration_configs WHERE tenant_id = 'tenant-001';

-- 更新配置
UPDATE collaboration_configs SET
    auto_review_threshold = 0.80,
    default_sla_minutes = 30
WHERE tenant_id = 'tenant-001';
```

### 5.2 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `auto_review_threshold` | decimal(3,2) | 0.70 | 自动审核阈值 |
| `auto_escalate_threshold` | decimal(3,2) | 0.30 | 自动升级阈值 |
| `default_sla_minutes` | int | 60 | 默认SLA（分钟） |
| `urgent_sla_minutes` | int | 15 | 紧急SLA（分钟） |
| `review_pool_filter` | JSON | null | 审核人员池过滤 |
| `escalation_rules` | JSON | null | 升级规则 |
| `priority_rules` | JSON | null | 优先级规则 |

### 5.3 审核人员池配置示例

```json
{
  "review_pool_filter": {
    "role_ids": ["role-admin", "role-reviewer"],
    "department": "content-review",
    "skills": ["content-moderation", "policy-compliance"],
    "max_load": 10,
    "online_only": true
  }
}
```

## 6. 最佳实践

### 6.1 触发时机

**推荐触发场景**:
1. ✅ AI置信度 < 0.7
2. ✅ 检测到敏感关键词
3. ✅ 涉及HR/财务/法律相关
4. ✅ 工作流执行失败
5. ✅ 用户明确请求人工介入

**不推荐触发场景**:
1. ❌ 常规闲聊（置信度 > 0.9）
2. ❌ 简单查询
3. ❌ 已知问题

### 6.2 SLA设置建议

| 优先级 | SLA建议 | 适用场景 |
|--------|---------|----------|
| URGENT | 15分钟 | 系统错误、安全问题 |
| HIGH | 30分钟 | 内容审核、业务关键 |
| MEDIUM | 1小时 | 常规审核、质量检查 |
| LOW | 4小时 | 非紧急、批量处理 |

### 6.3 性能优化

1. **索引优化**:
   - 确保 `tenant_id + status` 索引存在
   - 定期分析慢查询

2. **批量操作**:
   - 使用批量分配减少数据库交互
   - 异步处理通知

3. **缓存策略**:
   - 缓存租户配置
   - 缓存审核人员列表

### 6.4 监控告警

**关键指标**:
- 平均处理时间
- SLA达成率
- 超时任务数量
- 审核人员负载

**告警规则**:
```yaml
- name: "SLA超时率过高"
  condition: "sla_compliance_rate < 0.95"
  severity: "warning"

- name: "积压任务过多"
  condition: "pending_tasks > 100"
  severity: "critical"
```

## 7. 故障排查

### 7.1 常见问题

**Q: 任务创建失败？**

A: 检查以下几点：
1. 租户ID是否正确
2. 数据库连接是否正常
3. 必填字段是否完整

**Q: 任务无法分配？**

A: 检查以下几点：
1. 审核人员池是否为空
2. 分配规则是否配置正确
3. 审核人是否在线

**Q: SLA超时告警？**

A: 检查以下几点：
1. SLA配置是否合理
2. 审核人员是否充足
3. 优先级调整是否正常

### 7.2 日志查看

```bash
# 查看服务日志
tail -f /var/log/humaninloop/service.log | grep "task_id"

# 查看错误日志
tail -f /var/log/humaninloop/error.log

# 统计任务状态
mysql> SELECT status, COUNT(*) FROM collaboration_tasks GROUP BY status;
```

### 7.3 数据修复

```sql
-- 修复卡住的任务
UPDATE collaboration_tasks
SET status = 'CANCELLED', updated_at = UNIX_TIMESTAMP(NOW()) * 1000
WHERE status = 'IN_PROGRESS'
  AND updated_at < UNIX_TIMESTAMP(DATE_SUB(NOW(), INTERVAL 24 HOUR)) * 1000;

-- 清理历史记录
DELETE FROM collaboration_history
WHERE timestamp < UNIX_TIMESTAMP(DATE_SUB(NOW(), INTERVAL 90 DAY)) * 1000;
```
